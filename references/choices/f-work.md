# F. In this paper：直接命名总体工作与任务能力（4支）

先选本位置要建立的判断，再读所列来源的必要邻段和完整贡献集合。英文均为编辑抽象式，须换入本稿自己的事实后自然成文；同职责分支不是同义句。所列源句语法是来源事实，适用性与篇幅判断是编辑迁移。

语言实现：[L5](../realizations/operations.md#l5)。


### F1 工作＋表示核心

- 源：MOCK P5.S1。以条件概率表示上下文依赖并命名系统；后续句才给语料与调度
- 实现：“In this paper, we present [system], which models [task-relevant relation] to [overall task capability].”
- 适用：表示／关系改变是核心推进，读者已理解关系为什么重要
- 代价：首句不列全部部件；需要一段解释所选表示何以可获得

### F2 工作＋输出契约

- 源：FirmRCA P8.S1–2。总框架后直接给错误指令输出，限定crash来源
- 实现：“In this paper, we propose [framework] for [task]. Given [available input], it produces [actionable output].”
- 适用：题目或系统名无法让人知道实际交付，两句明确能给用户什么
- 代价：比一长定义句多句界，却分离任务身份与输入输出；避免输出扩大为全自动解决

### F3 工作＋关键资源条件

- 源：FreeEagle P6.S1–2。命名方法与任务，独立重申无需两类样本
- 实现：“In this paper, we introduce [method] to [task] without requiring [unavailable resource].”
- 适用：资源条件本身决定新能力，已有gap已经建立其必要性
- 代价：紧邻能力保留条件；不把without扩大为任何校准／训练都无需

### F4 工作＋与核心技术的最低必要关系

- 源：TextShield P4.S1–3。目的回gap，提出框架与任务范围；先总阶段，再解释三阶段的不同职责
- 实现：“To address [established gap], we propose [framework] for [task], combining [complementary operations] to [supported capability].”
- 适用：结合方式而非任一组件单独构成研究，后续必须写接口或互补关系
- 代价：技术名只保留能立即解释任务作用者；“combining”不能自行充当新颖性证明
