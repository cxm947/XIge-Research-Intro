Observed: no separate evaluation paragraph; numerical results first appear in B3. Challenge taxonomy has two firmware-specific problems plus a third shared problem, not a mandatory two-challenge universal scheme. P8 introduces a concrete data structure before revisiting the shared issue; the same event mechanism responds to acquisition and aliasing, while ranking responds to guidance.
Inferred purpose: the opening turns fuzzing's familiar success into an input for the unresolved analyst task, preserving the value of earlier work. The reader learns what must be collected before reading how it helps reverse execution. Treating all three challenges as independent inventions would obscure the shared event mechanism; grouping by provenance and then linking by response explains the engineering choice more faithfully.
