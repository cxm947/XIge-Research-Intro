# EMS关键位置：条件化内容分支与取舍

本文件是条件化编辑建议，不是源文事实或作者自述。每组先定读者尚缺的关系，再选信息和次序。下列示意句为原创中文；它们改变解释量或取材范围，不是声称英文原文只有换词差异。各方案只在列明条件下可用，不要求同时采用。正式稿既定布局优先。

## V1 入口：技术对象何时才能让大同行看见任务

源位P1.S1–S4：从操作到覆盖价值的解释量，取决于读者已经理解什么。

### A 从一次实际工作循环进入
- 适用：读者熟悉安全研究，却未必知道具体测试范式怎样工作
- 选择：先给输入材料、改变动作与执行反馈，再说明最想发现的结果；接着解释关键代理为何接近终点
- 原创示意：测试器反复改变输入并执行目标程序，从新出现的行为中寻找缺陷。要让缺陷暴露，测试首先需要触达相关代码，因此探索能否走进新路径直接影响发现机会
- 收益与代价：动作容易想象，任务价值无需另加宣传；需要两层解释，熟悉该循环的读者会觉得进入差异稍慢
- 本篇判断：原文接近此路，且第一句即含技术名；不是把术语全部藏到最后

### B 从大家共享的任务直接进入改进对象
- 适用：目标venue已共享工作循环，短稿篇幅紧，关键代理也无争议
- 选择：简短命名任务，直接说现有路线在哪种决定上有效，再引出待改进决定
- 原创示意：覆盖引导测试已能把计算投入更有希望的用例，并借助求解跨过困难条件。本文关注这些成功探索留下的动作信息还能怎样被后续变异使用
- 收益与代价：更快进入研究问题；大同行若不知道用例、条件与漏洞之间的关系，仍会被迫补猜，不适合无条件替换A
- 保留约束：这一缩写版不能随后又假设读者已理解全部局部接口

### C 从具体受阻的使用场景进入
- 适用：材料确有持续测试、重复运行等明确场景，主要价值是既有探索无法积累，而非单次吞吐率
- 选择：先展示同一团队反复测试的任务流程，再指出哪些结果没有转成下一轮可调用动作；随后给通用任务名
- 原创示意：一次测试已花时间找到能通过某些分支的输入修改，但下一轮仍可能重新尝试同类修改。若这些动作能在相同局部条件下再次调用，过去的探索便可能减少后续重复工作
- 收益与代价：积累价值更鲜明；会前置历史主题并延后领域路线，且需要真实场景证据。本篇没有以具体团队叙事开头，不能把此方案冒称原文事实

## V2 强已有答案：比较哪一个决定，而非比较谁有没有学习

源位P1.S6–P2.S5，补读§II-B／§III-A。

### A 按改变的决策层比较
- 适用：已有方法使用相似反馈或历史，但用于不同粒度的选择
- 选择：先承认资源分配或位置选择的能力，再说明当前希望输出的是具体操作及对应值；不要抹掉共有数据来源
- 原创示意：已有历史反馈可以帮助选择值得继续尝试的用例，或定位值得修改的位置。仍需回答的是：面对一个已知局部输入，能否把过去成功的修改直接变成下一次可抽取的动作
- 代价：需要把接口差异说准，少写一个名词就可能错置近邻。本篇背景材料支持这样的读者区分，但不是当前新颖性的独立证明

### B 按条件获取与重复成本比较
- 适用：最强已有答案已能解决目标条件，研究价值主要是重复任务下的成本节省
- 选择：先说求解确实打开困难路径，再说明哪些共享局部结果可能减少再次求解；把省成本建立在复用条件上
- 原创示意：求解技术能够处理随机变异难以通过的条件。如果后续目标包含相同的局部约束，保留已经成功的修改可能减少同类条件被反复解决的成本
- 代价：省成本成为重要主张，需要相应评价；若只测最终发现数，不能写成所有求解开销都已消除

### C 按剩余可见性或可用信息比较
- 适用：新材料确实不能获得前人需要的程序分析信息，但可以获得执行记录；这不是本篇引言已经建立的核心限制
- 选择：明确不可得输入，再限定历史能替代哪一部分判断，以及哪些问题仍无法处理
- 原创示意：当显式条件信息不可得而执行反馈可获得时，可以先研究成功动作能否支持受限的后续选择
- 代价：会改变问题条件，须查材料授权与证据，不能为了让故事更强就把“不做显式求解”改成“不能取得源码／约束”

## V3 动机证据：跨任务输入为什么值得纳入

源位P2.S7–P3.S9。

### A 先共同关系，再有限见证，再输入分类
- 适用：跨程序复用是读者最可能质疑的选择，已有机制相关的案例观察
- 选择：用共同局部条件解释为什么可能迁移，给一两类可观察表现，再命名当前与既往输入
- 原创示意：共享逻辑可能让不同路径重复遇到相似局部条件。相关代码现象提供了有限见证，因此可进一步研究当前运行与既往运行的成功动作是否都值得保留
- 代价：引言较长，但每项细节都承担一个跨越；不能把案例的代理关系写成每次迁移成功的保证

### B 先同任务积累，后把跨任务作为扩展
- 适用：同程序多轮数据充分，跨程序证据暂弱，核心结果不依赖跨程序
- 选择：主线只承诺同任务历史积累，跨任务写为后续考察，不提前把它列为主输入能力
- 原创示意：既往对同一程序的成功尝试可为下一次测试提供可用动作。跨程序是否也能复用，则需另行验证共享条件及其收益
- 代价：范围更窄、较少鲜明性，但不会让弱证据支撑主张。本篇确实有跨程序相关证据，因此不应机械缩窄其实际主线

### C 用直接受控迁移结果替换代理案例
- 适用：新材料已有足够直接的迁移实验，能隔离历史来源与其他变量
- 选择：先给简短可检验迁移现象，再解释共同条件；详细代理研究移到动机或分析章节
- 原创示意：在控制其他设置后，来自另一目标的历史仍改善了后续发现，这促使我们追问被复用的具体动作关系
- 代价：容易提前消耗实验结果，还可能让机制像事后解释；需真实受控证据，不能把本篇两个代码案例改名为已完成的严格迁移因果实验

## V4 挑战到方法：解释到哪一层才足够

源位P4–P7。

### A 先接口和部署约束，再按数据生命周期解释
- 适用：方法名容易让读者误想成黑箱或高成本学习，核心技术是把历史转成频繁可用动作
- 选择：给输入→输出；说明何时有新信息、调用频率；再写记录、接纳、表示、更新、调用
- 原创示意：模型需从当前字节得到可尝试的修改值与类型，并能吸收不断到来的记录。因而设计必须同时保留动作关联和足够低的调用代价
- 代价：解释较细，但每一步服务可用性；不必把所有字段都放入贡献列表

### B 先总体策略，再只保留一个决定性实现关系
- 适用：读者已熟悉数据与调用方式，新颖性集中在一条表示或选择关系
- 选择：一句说明复用策略，随后只交能解释新能力的转换；更新与宿主细节留方法章节
- 原创示意：我们将历史中的成功转换压成条件化的动作分布，使测试器可按当前输入直接抽取候选修改
- 代价：更紧凑，但若前文承诺在线更新或低开销，仍须至少给兑现依据；本篇不能仅凭这一句就完成所有方法解释

### C 按两种运行条件分别解释方案
- 适用：同一模型在离线部署与在线部署中有真正不同的资料来源和责任，强行一条流水线会混淆
- 选择：先区分预构与增量分支，随后给两者共享的动作接口；避免把它们写成两套独立发明
- 原创示意：既往记录用于准备初始选择，当前运行的成功尝试用于持续校正；两者通过相同动作接口参与变异
- 代价：双分支更清楚却可能重复公共结构；适合资料时间轴比表示本身更难理解的论文

## V5 方法思路与贡献：同一事实怎样换职责而非换同义词

源位P5–P7与P10–P11。

### A 认识与技术分组
- 适用：发现可复用信息本身是一项重要且有证据的推进
- 选择：第一项说新认识及它支持的能力；第二项说实现这种能力的表示与载体，过程细节不逐项列功
- 原创示意：认识交付是确定历史中哪类局部动作值得复用；技术交付是让这类信息成为可调用的条件化选择
- 代价：需要证明认识独立于“我们实现了系统”，否则容易把假设冒充发现

### B 统一系统交付，设计理由保留在方案段
- 适用：认识不是独立研究所得，主要创新是完整系统集成或特定部署任务
- 选择：一项确认系统及准确完成的任务，下一项只保留真正独立的新机制或资源，不强凑观察项
- 原创示意：交付一个能将持续测试记录用于后续动作选择的系统，并明确输入接口、支持范围及实际实现状态
- 代价：贡献更紧凑，但认识价值可能被读成工程常识；选择前需判断工作是否真的只有集成层推进

### C 技术交付与可复用资源分组
- 适用：研究另有可验证的公开数据／工具，资源本身支持新的研究或使用任务
- 选择：技术项描述能力，资源项描述内容、用途和可访问状态；评价另行确认结果
- 原创示意：除实现外，整理可复用的测试资料与接口，供后续研究检查历史积累条件
- 代价：只有资源实际存在且状态明确时才成立。本篇最终项包含未来开源承诺，不能据此写成已有完成的资源贡献

## V6 评价代表结果：选择回答，而非固定数字数目

源位P8与P12–P13，证据范围见evidence.zh.md。

### A 用一个任务总量和一个最相关比较预告
- 适用：前文任务明确、篇幅有限，读者首要问题是总体发现是否改善
- 选择：保总量口径与最相关参照；最相关未必是差距最大的AFL，也可能是宿主MOPT或更强的AFL++
- 原创示意：在所测程序与去重口径下，系统提高了总漏洞发现量；与宿主或较强对手的比较用于说明收益超过单纯继承已有能力
- 代价：少量数值易记，但必须把覆盖、条件变化或成本留到其他能被看到的位置。不能用主基线的最大增量替代所有比较

### B 先联合能力结论，再给机制与成本证据
- 适用：研究价值取决于“更有效且使用代价可接受”，前文还有收益归因问题
- 选择：主结果用定性且有范围的判断；随后选一个机制检查和一个受控开销结论，不必每句都给数字
- 原创示意：评价表明历史引导在多数受测目标上改善发现，附加分析检查了历史算子的作用，并显示受控设置下的执行代价较低
- 代价：主结果不如大数字醒目，却更贴合机制论文的读者疑问；机制检查仍不能自动升级为完全因果证明

### C 按尚未闭合的多项疑问保留长评价贡献
- 适用：自选目标、标准基准、初始化变化、检测器差异、跨程序历史、调用代价分别关系到核心主张
- 选择：每句回答不同疑问，主结果在前，其余证据只按实际支持范围陈述；没有必要把所有实验压成“效果优秀”
- 原创示意：先交主任务结果，再分别说明标准化评测、条件变化、归因和成本检查各支持哪一判断
- 代价：列表可能长，必须避免只是实验名称目录。EMS的八句例子支持这种条件化长度，不支持评价固定八句，更不支持最后贡献一定是评价
