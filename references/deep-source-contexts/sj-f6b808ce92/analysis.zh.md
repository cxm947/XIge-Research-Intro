# AdvSQLi：作者框架内的内容选择

本文研究公开论文的写作选择，不是攻击操作材料，也不声称已经验证写作收益。

指定来源：AdvSQLi，arXiv:2401.02615v3，2024-01-09，纪守领共同署名。[指定PDF](https://arxiv.org/pdf/2401.02615v3)。共同署名不证明个人执笔；本文不推断私人写作意图。

## 一、坐标及证据等级

- 源P1–P7、C1–C3始终指[已有完整引言句图](../../intro-source-maps/sj-f6b808ce92.md)的分析坐标，非原论文印刷段号。原图坐标不重编。
- “作者P1–P5”仅指当前作者明确采用的写作框架，不与源P1–P7等同。
- “源文明示”：原文确实说出或报告的内容；“文本观察”：句法、顺序、取舍和表格中可直接核查的组织事实；“编辑推断”：对取舍效用、读者加工和替代分支的分析，不冒充作者自述或心理实验结论。
- 页码均为指定PDF物理页。原文英文只保留极少短语；主要用坐标及原创中文分析。

## 二、源布局不能冒充作者框架

源论文的引言走的是：web风险与SQLi示例 → WAF防线及两类策略 → 云服务运维收益 → 未充分了解的现实风险与本文任务 → 两句机制概览 → 实验预览 → 三项贡献。强近邻与两个挑战集中在引言之后的§III。源P5还把gap、现实案例、提出工作、研究价值放在同一段。

因此，以下是明确标注的迁移，而不是对源结构的复述：

1. 作者P1“大背景→小背景→命名重要任务”：从源P1/P3/P4取连续收窄路径，再用源P5.S4–S5与§II补足研究任务名。不能把源P1只命名SQLi攻击的做法当成已经交代论文任务。
2. 作者P2“必要背景与桥梁”：取源P2的执行结果对照、P3.S2–S3的过滤位置与转发判据、P4.S3及§II-B的接口可见性。其职责是让后续困难可理解；不把源P5的未知漏洞结论提前复制成P2的主旨。
3. 作者P3“第一独立挑战”：从§II-A和§III抽出维持有效行为的实际要求，从§III/§IV-A–B抽出表示与执行语义不一致的观察，再极简交代强已有方法和剩余。源文并没有这一段，必须注明是跨章材料迁移。
4. 作者P4“第二独立挑战”：从§II-B、§III和§IV-C抽出有限探测下的二元反馈搜索难题；先交缺失能力，再给信息不足如何阻碍候选比较的关系。不能拿本方法递归生成后的终止控制来充当第二应用挑战。
5. 作者P5“提出工作与研究策略”：源P5.S4的总任务加源P6的能力链可用；§IV补理由。保留提出什么、为哪两项困难选择何种路线、必要输入怎样变为产物，不堆算法名。
6. 贡献：沿作者要求直接接三至四项。源三项分工可参考，但源P7的独立结果预览不必照搬；若作者稿没有这段，最后一项必须自行承担实验范围、主结论及代表性证据。

这六条是源证据到现有作者位置的映射，不增加新的论文框架。

## 三、按需使用

具体内容选择见[条件选择](choices.zh.md)，句群示范见[作者框架句群](author-frame-sentence-groups.zh.md)。每项都给出源位置、子句/句群职责、原文的选与舍、条件变化时的替代，以及“任务价值×读者理解”的编辑推断。它们是有条件的编辑选择，不是每稿必填清单。

数字和范围的使用边界见[条件选择](choices.zh.md)的A10–A12，并注意以下要点：

- 查询节省和运行更快是两个主张；本源不能把前者自动扩成后者。
- 方法优于强基线、七个对象存在弱点、语义验证成立，是三种不同证据范围，不能在一句中相互继承全部条件。
- 最高100%可支持任务上限，但一些基线也到100%；若要证明相对改进，应选同条件下能区分方法的比较。
- 严格语义等价不是由有限运行测试推得的普遍定理；本轮不以形式语言层级的提法为自动正确性证明。

## 四、来源阅读边界

本轮完整重读了指定版本引言；补读了问题、近邻和挑战、方法的相关解释、评价设计与结果、局限及运行开销附录。对正文的用途是核验引言取舍，不声称完整复现了研究，不提供payload集合，不执行攻击或查询目标，不核验现时服务状态或2026年的新颖性。

源文仍可能有宽泛概括、不精确措辞或正文间张力；分析会指出这些如何影响迁移，但不据此倒推出作者私人动机。
