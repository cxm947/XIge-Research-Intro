# Code Rewriting Detector：追加式研究选择分析

指定来源：[arXiv v3](https://arxiv.org/pdf/2405.16133v3)，2024-12-16，12页AAAI 2025作者稿。原文身份、PDF 哈希及审读范围见本来源登记。完整引言物理1–3页；正文回查方法、数据、表1–5及稳健性与限制分析。这里只研究来源如何组织论证与表达，不制作检测器，不声称写作增益。

## 先给可用判断

这篇引言的主线不是“文本检测差，所以用了重写”这一跳步。P3先把迁移效果由未知变为作者实测落差，P4解释旧信号为何缺少区分力，P5提出另一种可观察差异，P6才把差异升为检测假设，P7将假设变成可检验的得分计算，P8给验证范围与作者报告结果。四种认识地位必须分开：诊断旧法、观察新关系、提出指标假设、测试检测方案。

一个句子的外层报告框架可以是语法主干，读者最需要的命题却在内容从句内。典型是P5.S2：外层是作者观察，内层才是给定输入来源时模型的重写倾向；更深处的相似关系决定下一步能否形成指标。不能从“首分句/主句”机械推出语篇前景，更不能把最后出现的内容一律视为次要。P4.S10的比例、P8.S4的访问条件、C3.S1的稳健性都是后置但有关键新内容的部分。

C3不是纯收束。检测成效已在P8铺垫，但“鲁棒性”是贡献列表第一次加给引言读者的评价维度。它需要正文的条件变化实验承接。只说末项复述前文会遗漏这项新信息；只保“鲁棒”又会越过重命名退化与长代码反例。

研究理解、价值链、段落角色、反事实、正文证据、词汇及贡献分工，与八条保留子句分析共同使用。新的43个单元沿旧图身份逐一接到语法层级、语篇前景、首次新增、必要前提和明确替换范围的局部保义选项；另保留有类型标识的编辑变体。这不是43处旧错误，也不是用覆盖数证明深度。

## 价值与理解前提一同决定选材

1. P1–2先保代码助手的真实用途和收益，再引教育评价与工业审查。它们使检测具有现实用途，但不能证明来源判断修复漏洞、判定作弊或直接评估学生能力。源文的外部历史比例承担后果可信性，本轮未重查那些外部研究。
2. P3保已有文本检测及迁移未知，再报告失败。若直接从“不是为代码设计”推出“不适用”，就把需要实测的问题偷换为逻辑结论。
3. P4不给“代码不同”贴标签了事。语法限制→局部可选空间→低熵命名→有效区分信息减少，使读者能理解为何该换信号。图1的比例选来支撑“普遍性”，并不是新方案性能证据，也不足单独识别全部性能下降的因果来源。
4. P5的两侧对照比单独展示重写合成代码很相似更重要。缺人写对照时，同样现象可能对两类都成立，无法推出判别力。图2给直观可看对象，但两个不同程序示例不是配对控制试验，更不是对所有生成器的分布保证。
5. P6明确假设，P7保第一步配对、第二步相似得分、第三步多次均值。这条输入输出链让研究由直觉走到能评测的产物。若只给两模块名，读者不知道随机重写如何变成一个检测值。
6. P8的模型名单由外延问题选择，两基准结果由任务答案选择，访问条件由能否在封闭服务条件下实施选择。三者各答不同问题；不能将APPS/MBPP、四生成工具、三重写工具混成同一个分组。

## 贡献集合的选择逻辑

C1独立保留“发现落差并解释”这一知识产品。它既回收P3–4，也是方法改选的理由；不能仅把它看成写背景的方法。

C2以方法为主断言，访问条件紧随。条件没有为凑短句被删：它让读者知道所提关系在商业接口限制下仍有使用价值。zero-shot的正文定义是无需合成/人写来源标注训练，不是无训练；相似模型用未标注代码作自监督训练。

C3的准确性有P8的结果支撑，稳健性则把引言讨论扩到新评价轴。正文的提示、温度、长度与重命名分析让这一轴有可查内容，但源文也明确报告长代码区间某基线超过本方法，且大量重命名使检测接近随机。因此C3的意义是相对方法、特定设置的综合评价，不能改为绝对稳健。贡献末项可以新增必要的评价维度，并不是所有事实必须先重复在方案段。

## 证据为何放这里，细节为何留正文

以下是编辑推断，不是作者自述写作过程：

- 低熵比例放在诊断结尾，是对“数量够大、值得改变信号”的即时回答。若换成检测器最佳AUROC，则读者仍不明白为何现成概率路线不足。
- 两基准的结果放在实施链之后，使读者先知道被测试的对象。若把最佳单元格提前当卖点，会遮蔽跨生成器的测试问题和平均分数的含义。
- 相似模型的架构、训练GPU与采样参数留方法/设置，避免引言接口链被细节打断；但不应由省略细节推论无训练或无资源。
- 表4的替换实验支持两类操作都有贡献；表5的模型替换支持结果并非只绑定一个表示模型。它们适合回应实现归因，不能替图1变成低熵因果证明。
- 鲁棒性是在多变化轴上提出的概括。反例若改变声称范围，应保留到结果解释或贡献限定中，不能为一个好听结论默默删除。

## 已知未解，保持未解

20.5%、29.1%及约32%沿源文作为作者报告量保存。已读表3及其前后正文，没有明确到足以唯一重现这些总括数字的聚合式；不替作者选均值、重写次数或对照行，也不转换为百分点。表3与表4还存在特定StarChat生成列的数值不同，不能自行判定排版错、设置差异或调参影响。具体见evidence-and-boundaries。

只将文本说了什么与可定位图表视为源证据；关于读者认知、句子重心、备选适配和省略代价均为本轮编辑分析。不能由共同署名推断个人执笔，更不能把本册转成该作者的独特风格判定。

## 访问主体的必要消歧

实际需要可调用的是用于重写的LLM；待判代码的原始生成工具可以是另一个模型。可检测闭源工具的输出，与可调用所选重写工具，是两项不同条件。相似模型还可能需要自监督训练或外部嵌入服务。此处依据正文消歧，不能由引言的简写推出必须取得原始生成器API。
