# Evidence, utility and boundaries

Primary: https://arxiv.org/pdf/2405.16133v3. Physical page numbers below refer to the designated 12-page PDF.

- E1, Figure 1 on physical p.1 and Introduction P4 across physical pp.1–2: Llama-13B estimates a code/text token entropy contrast. The source reports over 70% of code tokens below entropy 1. Its role is to make prevalence credible. It is not by itself a controlled causal decomposition of detection failure. The y-axis label and decimal tick presentation should not be reverse-engineered into a new statistic.
- E2, p.2 Figure 2 and P5: two original/rewrite examples visually instantiate the contrast. The programs differ between source categories; do not describe this as a matched-control experiment or as distributional proof. Visual inspection confirms that the synthetic example remains similar while the human example is changed more substantially. Only the visual rhetorical role is claimed here.
- E3, pp.3–4 Methodology: zero-shot excludes training with human/synthetic origin labels; similarity representation is trained self-supervised. Mean cosine similarity over sampled rewrites estimates the score. Source Algorithm 1's output wording ties its label to G, while broader prose and cross-generator evaluations address synthetic code from other generators too. The callable model is the chosen rewriting LLM, not necessarily the original generator; a separate similarity model is still required. Preserve the broad source task and record the local notation tension; do not silently change the research task into identifying the exact generator.
- E4, pp.4–6 data/setting: APPS and MBPP detection sets are constructed; they are not simply off-the-shelf origin-detection benchmarks. GPT-4 sample counts differ from the other generators. Four generation tools and three rewriting/detector tools are distinct axes. Intro selections communicate applicability, while detailed counts and training conditions constrain evidence in the body.
- E5, pp.6–7 Table 3/Main Results: reported overall improvements are 20.5% and 29.1%; prose does not expose a unique aggregation formula. The earlier roughly 32% decline also remains an author-reported summary. These are neither independently reconstructed gains nor safely relabeled percentage-point gains. No attempt has been made to force a numerical match.
- E6, p.7 Table 4: the experiments replace rewriting by in-fill perturbation or similarity by tokenwise scores. This is a component substitution test, not literal removal of all rewriting/scoring capability. Under its stated setting, the combined route is stronger than these substitutions. The comparison should be described as component substitution, not removal of all rewriting or scoring capability.
- E7, pp.6–7 Tables 3/4: CodeLlama detector, StarChat generation, m=8 in Table 3 has 78.13, whereas Table 4's full CR+Sim row has 76.96; Table 4 does not state m in its caption. Other full-row values coincide with corresponding Table 3 entries. This is an unresolved source cross-table alignment issue, not a repaired source typo. It prevents silently reconstructing one shared configuration.
- E8, p.7 Table 5: alternative similarity implementations test representation dependence on APPS with GPT-3.5-generated code and multiple detector models. The source says alternatives still beat previous zero-shot detectors. This supports implementation flexibility within those tested conditions; not all embeddings or unseen languages.
- E9, pp.8–9 Figures 5–9 and paragraphs: prompt and temperature changes test consistency; code length includes a >1000-character interval where DetectGPT surpasses the proposed method. Identifier replacement tests 10/20/50%; the source says performance approaches random at the largest level and frames more complex adversarial scenarios as future work. C3's newly introduced robustness axis requires this scope. “Best under every condition” and “robust to arbitrary edits” are not supported.
- E10, p.9 Choice of m and p.10 Figure 10: increased rewriting counts improve estimation and observed detection with fluctuation, saturating around 20–32 in that test. Intro's sampling/averaging is justified as an estimate; do not promise monotonic AUROC or state four rewrites exhaust all gains.

The source's broad Deeper Analysis preamble says that all experiments there use GPT-3.5 as the generation tool, but its C++ subsection and table include four generation tools. Keep the subsection's explicit design when discussing C++; do not propagate the broad preamble mechanically. C++ is optional scope evidence rather than needed to explain the intro's two primary benchmarks.

None of the above independently replicates the detector, validates cited external prevalence data, or measures improvement in writing quality.
