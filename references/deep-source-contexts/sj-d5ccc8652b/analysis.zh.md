# ACIArena：研究产品、内容、语法与证据选择

## 1. 不是重贴benchmark标签，而是辨清产物职责

【源观察】P4把ACIArena称为统一评价框架，B1称为首次系统评估ACI鲁棒性的benchmark，B2交共享接口和模块化环境，B3交因素分析与设计洞察。P5虽提出ACI-Sentinel，贡献集未将其单列为第四项。

【编辑推断】“让MAS更安全”是远端目标，直接完成的研究任务是让不同系统在明确威胁及任务效用条件下接受可比较评价，再从结果形成安全认识。这样才知道哪些内容值得写：攻击面/目标是覆盖对象，系统实现与接口是比较条件，BU/UA和ASR是解读结果的条件，发现才是知识产物。已有底稿已说资源→接口→知识，本轮不是再发现这个三分法，而是把各类谓语、从句和例证放回其责任。

## 2. 三类限制看似镜像，却不能互相代替

【源观察】P3先列不完整威胁、非标准设置、有限扩展；P4对应Comprehensive/Standardized/Extensible。P3.S4另说攻击对系统/角色定制和内部访问的依赖。§3.2限定攻击者能力，§4.3用共同执行入口接入异构代码库，附录D给模块职责。

【编辑推断】镜像结构已在旧稿，不算新结论。真正需要进一步区分的是：

- 覆盖：测试了什么表面与目标。两轴并列和1,356例支撑资源范围，不能自动推出完全均衡的笛卡尔积
- 比较条件：被测系统、威胁权限与执行方式如何对齐。只有通用任务输入一致，仍不能充分比较攻击下鲁棒性，这解释MASLab让步句的重要性
- 扩展：未来研究怎样加系统/模块。它降低重建成本，但不是现有结果可外推到一切新部署的证明
- 权限：P3.S4另有实际适用条件。不能简单说标准接口已解决访问权限或任意现实攻击者均可操纵所有表面

因此不把每个旧限制机械配一个独创新模块。自然语言镜像帮助导航，真正的科学依赖要看不同条件支撑哪一种结论。

## 3. 评价任务设计比结果大数更能解释benchmark价值

【源观察】§4.1排除开放式评分难以清楚归因的任务域；在六个既有能力数据集取材后，用复杂性、可分解性和歧义三标准筛选任务。其明确理由是简单任务可能由一个仍正常的代理完成，从而掩盖其他代理受影响。§4.3规定案例由良性任务与攻击配对；BU和UA使用相同任务效用指标，ASR另评攻击目标达成。

【编辑推断】这部分能补深旧稿的“更完整MAS协作”说法：选择难而可分解的任务，不是为了增加难度名声，而是避免系统已受扰却由单代理补偿后看似无事。共享任务效用标尺则使低ASR与正常做题能力可以分开。基准的新增能力不等于“一张大表”，而是将威胁结果与原任务结果放在可解释的共同条件中。

这里属于观测/归因设计理由，不应强改成攻击算法挑战或模型训练优化困难。引言若需要多一句设计解释，可选“为什么任务应真正需要协作”，不必列每个基础数据集名称和打分阈值。

## 4. 语法主干与知识前景要联读

【源观察】P4.S3主干是提供接口，科学效果在ensuring；B2亦是provides主干，thereby部分给外推价值。P5.S1矩阵是experiments reveal，发现内容在that之后。P5.S3矩阵是propose名称，区别性思想在relative+by+from/to。B3矩阵offer，知识种类由名词补语与why/how内容交代。

【编辑推断】不能用“主句=新信息、从句=背景”的快捷规则。形式上附属的部分可能是读者最缺的关系。若要压缩，先保“接口统一使哪些比较成立”“从发现为什么得到防御方向”，再决定删significant、in-depth等评价词。最简单的主谓宾也能有效，只要输出对象与研究后果足够明确。

源P1.S2从能力转部署用了并列and，不能把编辑认为顺理成章的进展写成源已证因果。P5.S2的those developed是缩减被动修饰；若统称“关系从句”可解释功能，却不够精确教句法。P4行内标签和分号又说明分析单元不总等于印刷句子，篇幅不能按同一标点机械计分。

## 5. 结果选材：先决定本段要回答什么

【源观察】结果池有固定拓扑下角色改变、不同模型/任务域风险、角色风险随目标改变、BU/UA与ASR、传播指标、五类已有防御、ACI-Sentinel和自适应测试。§5.1的受控对照直接说明只变拓扑会得不完整认识；§5.2展示较低攻击成功可能伴随较低任务效用；§5.4展示防御转移失败及有时放大攻击。另有附录B.3的判据核验：从此前被筛除的良性任务中随机抽取50题，再结合攻击以包含成功与失败情形，三名标注者依据Disruption二元成功标准判定。GPT-4o与人类多数票在这次检查中达到98%一致；这不是对最初良性任务筛选评分的验证。

【编辑推断】这三个观察分别回答比较条件是否充分、成功/失败如何解释、旧评价结论是否能迁移，比只挑最高攻击率更直接证明统一基准值得建立。引言现有P5选防御迁移/反直觉放大，是回应P3所批评的设置局限；若换成ACI-Sentinel最大降幅，则全文中心会向防御算法偏移。

三个有条件选择：

1. 读者只信拓扑：用V04的受控对照，让研究认识更具体，但不塞进所有其他维度
2. 读者可能把不工作当安全：以BU/UA对照解释ASR，让安全评价不能单看一个数；保比较所用任务和实现范围
3. 读者怀疑自动评分可靠：可用附录B.3中50个此前筛除、随后结合攻击的任务及三人标注，说明GPT-4o对Disruption二元结果与人类多数票的98%一致。完整套件中585例使用LLM judge、771例用字符串匹配；该50题检查不是对585例或全部1,356例的代表性随机审计，也不验证任务筛选评分。它有限支持自动Disruption判定的可信度，不等于MAS本身98%安全，也不能替代鲁棒性发现

上述结果各有职责，不能因为都显著就全挤在末贡献。源未在引言逐条堆数的选择有合理任务依据，但不推出所有benchmark都不该给数。

## 6. 长短的责任而非配额

【源观察】P3最大，因为三个限制要交实例、机制后果和强近邻；P4用行内三特性承接，不另长篇列实现；P5只有三个实质句，先发现再给有条件失败再引辅助防御；贡献为3/1/1句。

【编辑推断】B1较长源于身份、案例内容、发布安排三职责。B2可一长句交产品与科学后果。B3概括因素分析时一句足够；如果要让具体知识更可理解，V08两句是信息增加而非违反风格。反过来，若所有条目都扩成三句，会把辅助防御或重复接口误升为同等独立贡献。

相对篇幅取决于读者尚缺什么推断关系：保强近邻、实际判别对象和研究后果；删重复的评价词或已知对象，不能删必要条件来换短。
