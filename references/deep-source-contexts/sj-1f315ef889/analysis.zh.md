# MPInspector：保留完整理解，补足信息接口与受控表达选择

指定来源：[USENIX Security 2021正式PDF](https://www.usenix.org/system/files/sec21-wang-qinying.pdf)，正文4205–4222，含封面共19物理页。指定版本与完整重建使用同一PDF字节。完整引言在物理2–4页/4205–4207，已通读并查看实际版面；必要正文依据另记。这里是完整重建的定点深化层；baseline-analysis.zh.md 和 baseline-clauses.zh.md 保留完整解释与66单元，当前资格就近约束历史表述。

## 先判断已有内容是否够用

既有档案已完成大部分实质工作：它分清实现与规范、黑盒限制、自然替代方案、两层挑战、方法数据流、结果层级、贡献归并，并把精确率/召回、模型验证、适配成本和威胁条件解释得很细。不能把这些已有认识再包装成新发现。

本轮只选择19个有具体深化理由的单元：把语法矩阵、语篇前景和新信息拆开；说明常规句式及局部篇幅为什么服务这个读者路径；检验旧备选是否保住输入关系；构造范围清楚的完整改写。其余旧单元保留引用，不因未重写而视为缺失。67个坐标含原66句及贡献引导，仅是来源覆盖，不是67条新分析。

## 主体方法论：研究价值和读者依赖同时决定写什么

论文的核心问题不是“能否把学习和验证器连接起来”，而是怎样自动检验定制且不可见内部的协议实现。这个研究对象决定三种不能省略的接口：实际交互到模型、规范加实现到待验性质、违例到真实威胁下的攻击认识。已有档案已识别这三层；追加分析说明它们怎样进入句法及篇章选择。

开篇先让读者知道协议连接哪些参与者，再展示平台定制和已知缺陷。接着才转到整体安全认识不足、专家人工成本及自动验证问题。这不是先堆IoT规模再突然命名工具。保留的P1是分析块，版面上实际上包含两个印刷段落；第二个从S6开始，把已知缺陷转成尚缺系统性认识。新的物理定位只帮助看清这个转向，不要求为编号重建全套分析。

P2的两层多样性先导致可扩展性压力，S5的标准/实现落差又改变参照的可靠性。后者不是更多实例，而是P5为何不能直接照抄规范性质的前提。P3再把闭源转为黑盒/系统无关要求，P4比较逆向和崩溃导向测试是否回答同一任务。如此，性质驱动不是一个无缘由的标签：它直接回应非崩溃逻辑缺陷这一输出需要。

P5先给整体数据流，再定义状态机的组成和真实可观察输入输出，最后才进入P6–P8的内部障碍。若直接列三个组件而跳过P5，读者尚不知道“消息语义”“交互逻辑”“安全性质”分别是什么，也无法判断三个改进各解决哪个缺口。前面的两项是外部问题条件，后面的三项是采用此框架以后必须处理的适配问题；数字不同并非矛盾，更不是可复制的固定挑战模板。

## 同一信息接口怎样在句内被保住或被删掉

P5.S3–S5分别为10、25、12个词的透明长度代理。中句较长，原因不是修辞华丽，而是它同时交代性质来源和精化依据：先从规范收集，再依据学得状态机精化。状态机有双重职责，既参与确定要检查什么，又成为形式验证的对象。

旧档提供的压缩B明确了实现模型和规范性质，却没有明确保留模型条件化精化这一关系。读者若在前文已经知道，可以把它理解为概括；但作为独立等义替代，它并非仅少了工具名。V1因此给出完整顺序版和结果前置版，都保留三步依赖。选择顺序版时，陌生读者容易跟随生成过程；选择结果前置版时，已经了解输入的读者先看到验证目的。这里比较的是信息入口，不宣称某版普遍更好。

P5.S8前置深查目的，再以关系结构说明详细语义落到定制参数组成；S10先说采用主动学习，再用同位定义交一般输入输出；S11才绑定到消息、响应和连接状态。这个先定义再实例化的常规安排，是源文选择的一条读者路径，使新工具名获得可理解内容。具体实例先行也可以，但须建立可观察对象，并清楚连接到一般框架；概念依赖不等于固定句序。它不是要求所有论文都必须解释主动学习；若受众已知，可以减少定义，但不能同时删掉本文自己的观测接口。

P6.S4先承认真实流量模式匹配能处理有些常见函数，再用while给未知定制类别的剩余问题。S5以文档通常包含这些参数信息为前提，说明直接抽语义的另一证据来源。两句的力度不同：部分/可识别、几乎不可能、通常提供，不能全改成简单的成功/失败二分。旧段的证据分流认识保留，但旧P6 A/B应标为上下文概括：A省去some/can，B仍省some，两者都压掉未知函数模式近乎不可定义及文档通常提供信息的前提，不能继承其笼统保义标签作为严格等值认证。这不表示它们在已有前提的上下文中无用。新V4只检验把S4对照从句拆成独立句后，能否保持对象和强度，并不代替S5。

## 语法位置、研究前景与结果责任并不重合

P1.S8以问号结束，但语法矩阵是“亟待回答的问题是……”，how结构嵌在补语内。说它在篇章中提出问题没有错；把它当成无矩阵的直接疑问句则会丢掉问题的被强调方式。

P7.S1在一个46词句子中交环境、不能直接使用的判断及两项原因；这里的较长形式帮助读者理解为何应改造既有框架，而不是抛弃它。后面的停止条件句仅20词，因为运行不确定性的背景已经由S2/S3交代。若将短停止句扩为一般完备性保证，就是改变科学主张，不是把措辞写得更有力。

P8只有两句仍完整：验证器可能卡住；作者用脚本调整求解目标顺序。S2的关系结构定义oracle是什么，目的结构说明它做什么。新验证器、改变安全性质和让既有验证器能够完成，是三种不同成果；源文只支持后者的具体设计与案例。

P9.S3的语法矩阵是平均耗时，精确率在with附加部分；研究前景却是成本和已报正确性双轴。V2把它改成两个句子，目的只在于让两项评价获得同等句法地位，数值、平均范围和精确率对象全部保留。它既没有把100%删成模糊较好，也没有扩大为召回或全部模型正确。

P9.S4最值得保留的是角色切换：主句是工具检查性质、检测违例；后部明确有作者进一步识别攻击的动作。数字57、252、11分别属于不同层，不是三种可相加的漏洞计数。V3拆句以显出主体和依据，不能把全部动作并为工具自动生成11类攻击。P9.S8再以研究表明为矩阵，把三项根因放在内容从句中；这些认识回收实现落差，并加入资源和共享环境，提供超出工具演示的研究价值。

## 为什么两个贡献组够用

旧档把贡献归为工具与实证，是已经成立的分析，本轮保留。C1.S2的精确、可扩展、可配置虽然句法并列，证据职责不同：精确率有§5.4评价，扩展性由§4.8的适配设计说明，配置性由输入要求及不同被测实现支撑。旧profile把三者一概称为已验证，容易让读者误以为全新协议迁移也有同类实验；追加层修正这点，不削弱源文原有能力宣称。

C2则保留违例、攻击组合和厂商反馈三个层级。数量不能替代现实威胁条件，作者报告不能替代外部回应，得到部分厂商承认又不能改成全部修复。清单每组三句的篇幅来自职责差别，不必为了排版补一个“实现三个模块”的第三贡献。

## 受控改写怎样使用

variants.zh.md给四个完整上下文案例，其中V1包含两种完整布局。均明确覆盖哪些源句、前后读者已知什么、语法/信息顺序改变什么、科学命题不能改变什么。三个局部目标另有句内/绝对字符边界和哈希，只有V2/V3/V4的指定结构作为局部对照；中文语义表达不是可直接插入英语原句的文本补丁，完整版本用于检查上下文。

文档补充未识别语义、验证依据学得模型、只评价已报违例精确率等科学条件保留在独立证据账，不把每个保义改写都改成更弱的新主张。若编辑要缩窄作者主张，必须标为主张变化；谨慎和等义并不相同。

## 事实核验单列，避免替代写作方法

本次核对的原文事实延续旧档：100%是已报性质违例的精确率；只有四个实现的状态机有源码或厂商帮助对照；三类协议、九平台、十实现不同；新协议扩展仍需一次性专家投入。45名审查者、Aliyun MQTT语义精度96%而CoAP为100%、94.87%的额外文档抽取结果、4.5小时的作者平均报告等并非本轮才发现。

这些内容放在 evidence.zh.md 及相邻资格中，是为了界定表达能承载的证据，不将来源分析变成查错清单。物理栏定位、旧压缩句的缺失关系及能力证据种类是实际修正；其余完整研究理解保留。本分析未重现实验，也不声称写作质量增益。
