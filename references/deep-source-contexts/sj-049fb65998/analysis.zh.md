# IMMI：让研究判据、读者信息与表达结构共同推进

指定主源为[USENIX Security 2024正式PDF](https://www.usenix.org/system/files/usenixsecurity24-liu-dinghao-detecting.pdf)，正文4069–4086，含封面19物理页。指定版本与完整重建使用同一PDF字节；完整引言物理2–4页已通读并查看实际版面。baseline-analysis.zh.md 与 baseline-clauses.zh.md 保留完整研究理解和60单元；本文件为定点深化，与相邻资格共同使用。

## 已经完整的内容，不重新包装为新发现

旧档已经有很好的研究理解：先承认全生命周期追踪这一直观答案，再解释规模问题；再给出配对/相似方法的真实能力，区分函数内部正确性与正确参照可得性；用对象释放责任统一不同症状；把LLM放在新判据之后；按判据、实现、现实产出组织贡献。它还准确区分总代码分析时间、人工真缺陷、维护者确认、误发现率和LLM消融代价。

本轮不重做60句。只选12处补足精确句法层级、双条件的非对称措辞、工具主次、目的与结果、完整改写的使用条件和代价。其余48个既有单元不因此被判成缺失。全部源坐标是可追溯基础，不是新增分析数量。

## 一条研究选择怎样连续控制缺口、概念与设计

论文并不是因为“内核很大”就采用新工具。P2先让读者理解：如果完整知道某对象何时分配、释放和再使用，许多错误已有直接判据；困难在于在复杂内核里取得这些信息。P3的近邻因此并非失败者，它们用配对或相似参照减轻分析负担。

P4又把问题拆成两个不同前提。一个是正确调用一对函数，并不保证函数内部真的完成资源管理；另一个是有些目标代码没有足够重复或正确参照。两者不是因果链，不能写成第一种缺陷制造了第二种缺陷。前者要求深入对象行为，后者要求新的比较关系不依赖另一份正确片段。

P5给出的关系是同一对象在特定错误情境下的释放责任。先交应该存在的协调要求，再把责任重叠和空缺分别接到不同错误症状，最后命名不一致意图。已有档案已解释这个统一视角；追加分析强调，文本的观察身份、条件和模态同样是研究内容的一部分。它并没有声称读取开发者心理，也没有把所有内存缺陷归入充分必要定理。

P6才将这个关系转成启发式和对象方法，并交代程序结构、注释及隐式机制如何提供证据。LLM因此有具体职责，而不是用时髦技术代替研究判断。切片/摘要解决的是取得足够信息的成本。三项优势依次回扣规模、参照、函数配对，读者无需自行猜测每项模块为何存在。

这样的次序是源文在当前读者知识下的一种可理解选择。换成已熟悉生命周期分析的受众，可以压缩P2；若受众不懂配对或相似检测，直接进入“无需参照”的优势就需要补课。可迁移的决定是保住依赖，不是固定段数、句序或两限制三贡献的模板。

## 句内的重点，并不总在语法主句

P4.S5的矩阵只说内存错误仍存在。前部条件设定内部缺陷，中间例子说明释放函数可能没有完成其职责，末部despite让步将正确配对用法置为已承认条件。研究前景恰在这个反差：调用用法正确不足以推出内部实现正确。V1把例子放到结论之后，适用于想先交清楚反例逻辑的段落；代价是读者要等下一句才知道内部缺陷具体指什么。

P5.S3的严格矩阵是作者的关键观察是某个that内容命题。关于共同问题的判断在内容从句，插入的despite承认症状差异，冒号交代共同问题，末部when限定提前释放情境。旧账本的语义理解保留，追加层将观察归属和内容命题分开；不能把这个结构简化成一条无归属普遍定理。

P5.S5/S6的责任重叠与空缺看似完全对称，形式却不相同：第一句用could，第二句在给定条件下说内存仍占用。第二句只有前一句一半的词数，因为neither与this已经能回收角色和责任。V2完整保留双句，不把单句的指代摘要当可独立使用的定义；若交换次序或单独引用，须重新建立对象及失败场景。

P6.S2把对象方法放在主干，把LLM增强放在分词补充里，末部不定式交推断目标。语法补充不等于科学上可有可无，但这一包装确实使分析单位先于辅助工具进入视野。V3将目的前置，适合读者需要先被提醒任务时；若前句刚给过任务，目的前置也可能多一次回顾。它不改变LLM已经参与增强的作者主张。

P6.S4以This enables回收共分析并作能力宣称，不是在此报告一个独立的意图准确率。P6.S7用thereby把有限分析量接到避免长程数据流的价值；它仍然做静态分析，不能压缩成“不需要任何数据流”。这两个短语分别承担能力和后果，不能因为都有积极结果词就当成同一证据。

## 常规形式与相对篇幅服务什么读者状态

词数仅按公开说明的空白分词代理统计。P4的13词承认句和7词转折句只负责建立对近邻的公平基线；技术理由还须由后面的前提和实例完成。S5需要40词交条件、例子、结论与让步，S6的24词则打开另一类参照问题，不能拿“压短”当唯一修订目标。

P5的观察句36词，把关系命名、症状让步和场景限定压在一起；后面30词与15词的两个条件例，通过一次定义角色再用指代节省重复。短句的可读性依靠前文信息已经到位。如果没有那些已知对象，照抄短形式反而会使读者补猜。

P6的15词方法句、26词证据句、13词能力句分别承担对象/辅助、证据类型、能力回收。这里的长度变化与职责对应，不是在倡导固定节奏。P7.S6只有21词却容纳两个不同指标，密度来自前文已建立报告与模块评价背景；拆开能够提高代价的可见性，也会占用更多篇幅。

贡献C2最长，并非三个部件各需升为独立贡献，而是它要证明新判据可实施。P9.S3把对象切片与按需摘要作为同一引入动作的两个宾语，用目的结构关联分析效能；它陈述设计职责，不自动等于证明达到了最优平衡。C3的15词结句则不重复所有数字，而从已报发现和维护者处理归纳应用价值。

## 结果选择及改写的实际使用条件

P7先给完整系统成本，再给80项发现及多数外部确认/修复，然后明确35%误发现率及LLM收益/代价。这一选择让读者判断排查负担与实用价值。若只取静态部分约9分钟，会把完整工具成本换成子组件成本；若只取43%减误报，就少了作者同时交代的漏报代价。它们属于信息选择变化，不能称为简单保义压缩。

V4把while中的漏报代价展开为独立句，让收益和代价具有更接近的句法地位；保留43%、4%以及作者的有效/仅这一评价力度。各自的分母和适用范围另在证据账说明，不偷偷加到源句里，也不以更谨慎为由把源文数值和强度改掉。

四个完整案例分别检验条件/让步、双条件指代、分析单位与增强手段、模块收益与代价。三个局部结构另有字符边界及哈希，但它们不是能直接嵌回英语原句的中文补丁；真正可检查的编辑结果是附有前后背景的完整中文变体。旧档三段原创选项也继续保留：它们已经说明压缩、省略和增加数字负担，不需要再为数量制造同类版本。

## 科学证据核验与写作方法分开

已有事实边界继续成立：80项为人工判断的新缺陷，投稿时72项获社区确认或修复；LLM的43%/4%来自模块对照，不能当全内核精确率/召回率；合成40项测试是另一实验；跨工具时间来自不同版本和环境，不是统一跑分。这里并未重新发现这些结果。

额外需要保留的细节是：源文用35分钟作概括，表1记录35分12秒，不把概括句变成严格服务时限。释放后置空等安全情况在正文会被过滤，责任重叠的说明仍须保持可能性。LLM误判释放函数已释放全部资源的案例，也说明“不依赖函数配对”不等于任何辅助推断都不会重现类似假设。

这些放在 evidence.zh.md 与相邻资格中，作为表达不能越过的范围；主体仍是从任务价值、强近邻与新比较关系推导内容选择。本分析未重现实验，不作写作质量增益或当前内核安全状态的宣称。

## 源形式与解释精度

P10.S3是as名词短语与for动名词结构，不存在to不定式；P8.S2的结果关系可理解，但逗号后直接接thus is不宜当成常规协调模板，补连词或主语应明确是编辑规范化。P6.S4的精确推断与细粒度分别表达，不创造量化准确率或完全正确证据。
