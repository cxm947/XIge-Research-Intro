## 真实任务、最强已有答案与新的分析单位

真实任务是操作系统内核内存缺陷的静态检测，主要研究错误处理时跨函数共享对象的释放责任。不等同于通用LLM代码审计，也不承诺找到所有内存缺陷。直接且合理的答案是追踪对象生命周期：该释放而未释放产生泄漏，释放后访问或再次释放产生损坏。困难不是判据未知，而是全内核路径、状态与跨过程分析代价。

轻量近邻采用分配/释放函数配对或相似路径参照。引言给出各工具真实用途，再指出两种残余条件：配对函数内部仍可能实现错误；专用代码没有足够重复样本或正确参照。新的观点是把对象的释放责任作为分析单位：调用者与被调者若都承担清理会重复，若都推给对方会遗漏。同一关系解释不同表面错误，因此有理由造统一判据，而非只换一个工具名。

正文§4把启发式落实为对象切片、释放/重置摘要、调用方与被调方意图推断、冲突检测；还保留单函数不同错误路径之间的不一致。重置为空会使重复释放安全，故简单“责任有重叠=漏洞”需先排除安全情况。LLM帮助解释注释、引用计数和回调等隐式行为，调用仅在静态分析先报不一致后进行。它不是事实真值：方法仍有路径、别名、调用深度等近似。

## 段落设计：同一个缺口同时控制内容与读者负担

P1（6句，p.2右）从内核中介位置到内存实际用途，再到漏洞类别、稳定性和安全后果，最后提出系统检测需要。连用功能与后果的价值是把对象和损害绑在一起；若受众已熟悉内核，可以压缩首句，而不削弱后文。这里无须补更大的AI背景。系统风险只是立题，具体研究价值仍要等后续指出当前可检测盲点。

P2（4句，pp.2–3）先说直接答案，再用判定例子建立生命周期概念，才引规模阻碍。这个承认让读者理解“为什么不用最显然的方法”；2800万行不是单独炫大数字，而是路径/状态爆炸的规模载体。P3（8句，p.3左）再给配对与相似路线，分别解释它们如何减轻追踪。工具名的作用是承载能力差异，不是文献数量展示。

P4（9句，p.3左）先肯定有效，再拆掉两个默认前提。第一缺口以函数内部释放不完整的反例落地；第二缺口以常共同出现、至少一条正确释放路径等来源说明参照如何取得。最后专用代码缺参照，把方法限制重新连到目标内核环境。两项局限并不要求后面写“两大挑战”；它们为改变检测单位提供理由。

P5（7句，跨p.3两栏）从错误路径释放资源的职责进入“谁负责”的一致性要求，以责任重复/责任空缺两条条件句推导不同漏洞，再概括为意图不一致。这里的意图不是读心，是程序行为与注释可提供证据的责任推断。作者明示共同根因；把两类表面错误并置理解为降低读者概念负担，是编辑判断。P4说缺少正确参照，P5的责任关系让读者看到不必找到“另一份正确代码”也有可比较对象。

P6（9句，p.3右）先命名判据，再给对象分析、LLM、结构与自然语言证据、切片摘要，最后逐一回收长数据流、稀缺参照与函数配对限制。LLM后出现很重要：研究价值先由新判据建立，工具只补解释能力。三条优势是与前文前提的对应，不是对LLM万能性的宣告。正文§3才展开两项实现难点；不能为了形式整齐把它们强塞进引言。

P7（7个研究/状态句＋贡献引导，p.3右）用LLVM与Linux落地，先报分析时间，再报新漏洞类型与维护者状态，然后给35%误发现率及LLM43%减误报/约4%漏报代价，最后是开源计划。代价与收益紧邻，使读者能估计实际排查成本。相比只说“有效高效”，这个段落提供可判断的证据，却没有把开源计划写成既成成果。

## 三项贡献作为完整集合

C1/P8，两句加标题：新判据是什么，以及它不依赖何种输入条件。创新不是单纯“使用LLM”，而是适用于缺重复参照代码的对象级意图检测。C2/P9，四句加标题：先引实现技术，再列对象框架、切片/按需摘要、LLM辅助。它最长，因为必须解释实现新判据的协作部件；这些部件不应拆成三项平级研究贡献。C3/P10，三句加标题：80项发现、报告/确认状态、实际意义。结果不是再报所有数值，因为P7已承担误报、时间和模块代价；贡献末尾保留实际验证链。标题是名词片段，不与科学陈述混计。精确词数未作正式语言统计，句长与条数只作信息分工描述。

三项分别回答视角增量、可实施性、现实产出，长度不必一致。结尾的“结果支持安全提升”是归纳，不是独立实验结果，也不是证明整个内核更安全的量化估计。

## 重开正文数字池：选择的好处与必要边界

- 表1/§6.1，p.12：总35分12秒，其中LLM I/O 25分49秒，静态部分约9分钟。引言35分钟回应原始扩展性障碍；若改选静态9分钟，会掩掉完整工具实际代价
- 表2/§6.2：123个唯一报告，经人工分析80个真缺陷；投稿时72项获社区确认或修复。引言“多数”是可维持状态限定，80并不等于80均有维护者确认
- §6.2：35项无需跨过程，另22项跨一道边界、14项跨两道、9项三道以上。它比总代码行数更直接支持局部责任足以发现缺陷；放入引言会转重为机制解释，代价是读者先学更多分析分类
- §6.4，p.13：人为注入20双释放和20泄漏，发现20与17；漏掉3项因调用链超阈值。40样本不是全内核漏报率估计；引言约4%来自另一项LLM消融，不是本测试的3/40
- §6.5：关闭LLM后多出3真缺陷和32误报，误发现率由35%升至47.5%。43%针对被去除的误报份额，4%是丢失真缺陷的约数；不要改成准确率提高43个百分点
- §6.5 Fig.8：LLM从释放函数名称误推其释放全部资源，恰好重现引言批判的“函数对内部正确”假定。因此收益机制与失败模式必须同读；新增LLM并不使该前提逻辑上消失
- §6.6表4：IPPO/HERO/MLEE分别与IMMI发现重叠28/24/26项，Goshawk无重叠。时间与精度引自不同内核版本和环境，作者明示只宜高层比较；MLEE缺源码和权重，使用保守重构规则。引言没有把35分钟直接改写成统一环境下最快，是合理的比较强度

作者明示选择四级调用上限，因为再深收益小且代价高；单函数局部资源错误不在主要有效面。误报中不可行路径占44%、错误路径识别26%、别名12%，说明下一步不只是换更大模型。关于引言为什么优先总耗时/真实发现/LLM权衡，而不选这些细项，是编辑推断。

## 可迁移表达与编辑选项

以下为原创改写，非引用或已证优于原文。

1. 残余前提版：Correctly pairing allocation and release calls does not ensure that the paired functions manage every object correctly. A detector therefore needs evidence about each object's cleanup responsibility. 两句先区分调用正确与实现正确，再给证据需要，比罗列工具更紧，但会省掉“缺少参照片段”这一不同障碍，后面仍须补足。
2. 观察优先版：When callers and callees disagree about cleanup responsibility, both may release an object or neither may do so. IMMI uses this disagreement as a detection signal. 对称条件把两漏洞用一个关系解释，省去具体LLM和优化，适用于先教概念的段落，不足以充当方法贡献全文。

相邻变体资格：本段完整英文是概念性编辑选项，不是两条源例的逐句等值替代。P5.S5以could表达第一类可能结果，P5.S6在给定空缺责任条件下断言继续占用及泄漏；当前V2保留这种非对称力度，不把两句统一改成may。
3. 证据校准版：On Linux 5.18, IMMI reported 123 candidates, of which 80 were manually validated as new bugs; its LLM component removed 32 false reports while missing three additional real bugs. 更明确分母与代价，篇幅和数字负担都更高，且需另补时间以回应扩展性。

可借鉴的不是固定“两限制、三贡献”格式，而是先承认直接答案与最强实用近邻，再找可操作的新比较关系，使模块、证据、边界都围绕同一研究选择安排。
