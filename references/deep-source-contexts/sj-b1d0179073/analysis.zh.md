# Prompt leaking：从实际暴露到可部署防御的四问链

主源：https://arxiv.org/pdf/2606.18673v1 ，2026-06-17 v1，23 页。本次获得指定 PDF，来源散列见本来源登记；完整 Introduction 在物理 pp.1–2，补读 §3–7、评测表与案例。下列 P/S 是本次语义段落/句序，B 是贡献项目；不是出版社原编号。所有中文均为原创释义。O=可直接观察的措辞/结构；A=论文明确给出的理由；I=编辑解释。共著不等于任何一个人的独立写作署名。

## 研究任务先行
实际任务不是再证明可诱导模型输出提示词，而是：在跨平台应用生态中判定暴露规模，检验防御是否保留正常功能，再用内部观察指导适合平台方的防御。最强近邻是保持模型权重不变、把系统提示转换成软表示的 PromptObfuscation/SysVec；其保护能力被明确承认。剩余问题是系统提示承载复杂业务逻辑，有限训练问答可能不能保存全部功能。AREA 保留文字系统提示，只训练附加软块，还联合注意力、拒绝行为和正常输出保持目标。由此，文章的价值单位是受保护且仍可用的应用，不是单独更低的泄露分数。

§3 限定攻击者为公共接口黑盒交互者，防御者为可访问模型权重的平台方；不改权重不等于普通闭源 API 用户可自行部署。§4 的每平台 200 个分层样本不是全平台随机普查；泄露部分依靠开发者确认，另一部分依靠十次输出中至少七次一致及双人审阅，不能等同所有样本都有原始提示真值。§5 的 LeakBench 是 50 个任务提示、模型特定攻击和约 5,000 个正常查询，不能混作测量中的 1,200 个已部署应用。§6 注意力分布、首 token 分布和 logit 分解支持内部机制解释；不是排除其他机制的单因素因果证明。

## 逐句、分句与段落组织
**P1 · p.1 · 应用资产，3句。** 出口：系统提示必须被保护，且它不是可随意抹除的附属文本。
P1.S1：O 主语是 LLM，谓语写其已成为应用基础，关系从句把生态转成面向用户的部署；I 读者先有能力进展常识，新信息是风险的承载场景，避免先介绍攻击术语再补价值。
P1.S2：O 早期应用和先进代理以对照分句并列，两个谓语分别是依靠提示、整合工具；I 对比不是淘汰前者，而是给后文跨平台异质性预存分类，后接 §2.1。
P1.S3：O 主句把系统提示判为关键资产，原因从句同时给业务逻辑与敏感信息；A 两种价值理由并置。删去业务逻辑会让后文 usability 指标失去动机；删去敏感信息会削弱安全后果。
**P2 · p.1 · 威胁升级，4句。** 出口：这是功能及信息资产风险，而非提示词趣闻。
P2.S1：O 转折后攻击成为主语，手段状语解释诱导暴露；I 接住资产名词，先让读者理解发生了什么，§2.2 回收。
P2.S2：O 既有研究作证据主语，主谓说明可重建，分词结果连接知识产权和隐私；I 承认技术可行性已由前人建立，留下不同的新问题。
P2.S3：O 程度递进，事件报告支撑泄露可能引发后续风险，例示从数据到工具约束；I 保留可能性而非把所有泄露等同实际接管。
P2.S4：O 前置分词把 OWASP 分类解释为对这些实际后果的回应；I 权威放在机制/案例之后，承担外部确认而不替代理由。
**P3 · p.1 · 既有答案的外推边界，3句。** 出口：需要跨平台测量。
P3.S1：O 让步承认安全对齐及防御建议，主句仍判断实际安全状况未知；I 已知措施≠已知结果，问题被准确放在部署层。
P3.S2：O 再一让步承认已有泄露研究，主句限定规模和平台数；I 不使用无人研究的虚假新颖性。
P3.S3：O 单平台研究作主语，其外推困难由不同底模、不同应用形态的原因从句说明；A 不是样本越多天然越好，而是选择维度与异质性相配。
**P4 · p.2 · RQ1，4句。** 出口：暴露普遍且有实际后果，下一步应问防御。
P4.S1：O 目的状语承接上述外推边界，作者谓语是调查流行程度；I 第一问严格接问题，而不是先报新工具。
P4.S2：O 覆盖范围先作方法状语，发现主句后用冒号具体化超过八成；I 分母先于比例，读者可判断结论范围，§4/表1。
P4.S3：O 泄露提示成为主语，敏感内容为新增宾语并列举类型；I 把频率转为严重性，但正文 access secrets 仅1.6%，不可把敏感密钥说成普遍。
P4.S4：O 作者披露与厂商定级并列；I 行动和外部响应分开承担证据责任，不能把两个厂商的响应推广为六家同级。
**P5 · p.2 · RQ2，5句。** 出口：安全与可用性是联合问题。
P5.S1：O 上段的高暴露率成为主语，冒号后疑问句引出防御有效性；I 前一研究结果产生后一研究必要性，避免四个孤立目标。
P5.S2：O 被动引入已有策略，关系从句完成三类划分；I 分类只保留将被比较的维度。
P5.S3：O 转折主句把未知限定为实际设置下的实用性，避免否认上一句已有方法。
P5.S4：O 目的前置，作者并列建 benchmark 与评估；插入同位语说明来源，后置维度/攻击种类界定覆盖。I 一个长句承担协议承诺，§5.2兑现。
P5.S5：O 对称对照两个方法群，保护与功能在每侧交叉配置；I 不设单一冠军，给 AREA 在保护与可用性权衡上的价值腾出位置，§5.3/表2。
**P6 · p.2 · RQ3，7句。** 出口：防御应针对注意力竞争，而非仅增加更强口头禁令。
P6.S1：O 时间/逻辑前置限定先理解再设计；I 说明分析工作为何在系统论文中占篇幅。
P6.S2：O 防御指令作主语，常见部署方式后附原因；A 保留功能是人们使用它的理由，旧方法有合理性。
P6.S3：O 转折及尽管成分让攻击成功与已有保护共存；I 问题从缺少防御改为防御失效。
P6.S4：O 因果连接后作者做机制分析，分词短语限定为竞争指令处理；I 研究对象比泛泛可解释性更窄。
P6.S5：O 视角状语先设观察层，主句命名现象；I 名称在可观察内容之前短暂出现，下一句立即偿还定义负担。
P6.S6：O 时间范围限定生成早期，注意力位移双向介词结构，从防御转向攻击，结果分句说明防御影响变弱；I 此句才赋予名称可检验内容，§6.2。
P6.S7：O 分析作证据主语，并列两因素，关系从句合并其竞争优势；A 作者提出驱动解释；I 应保留为该设置的解释，§6.3 的 logit/softmax 观察不证明唯一根因。
**P7 · p.2 · RQ4及方法结果，6句。** 出口：保留原逻辑并重锚注意力有可测收益。
P7.S1：O 最后标记完成问题链，动机分词后疑问同时包含抑制泄露与保留功能；I 回收前两问及第三问机制，而非新增指标。
P7.S2：O 作者提出命名方案，同位语交代 prompt tuning 来源；I 名称与来源只用一句，不挤掉做法。
P7.S3：O 关键思想作主语，不定式明确插入位置，关系从句解释重锚及不改变原逻辑；A 方法因果链与 P5 的功能损失直接对应，§7.1–7.2。
P7.S4：O 作者评估/比较并列，点名最强近邻；I 比较对象有识别度，避免只与弱基线比。
P7.S5：O 结果作主语，保持相当保护为前提，随后报平均功能提升和优化提速；I 选择的是联合实用性，非宣称所有安全指标最好。
P7.S6：O 追加三应用案例，结果分词承担应用场景佐证；I 案例不是前述跨平台测量的重复。正文限定（§7.8，物理pp.11–12/Figure 9）：作者用 AgentScope 和 Qwen3-30B-A3B-Instruct-2507 部署 persona-oriented ReAct、rule-intensive ReAct 和 RAG 三类应用；受框架限制，软提示被映射为硬提示。案例比较 AREA、PromptObfuscation 与无防御，SysVec 因中间层注入不兼容被排除。因此这里验证的是该案例实现与比较范围，不能回填成原始嵌入式方案已在六商业平台部署成功。
**B1–B4 · p.2 · 全部贡献。** B1.S1–2 以测量范围/发现为核心，第二句给披露及外部定级；B2.S1 用建立与评估并列，把 benchmark 和发现权衡绑定，避免资源孤立；B3.S1–2 先写注意力现象与成功攻击密切关联，再写因素分析，强度比 P7.S1 的根因更审慎；B4.S1 将防御动作与 benchmark/案例验证并列；案例的硬提示映射版本与不含 SysVec 的比较范围见 P7.S6，不能把两条证据路径当成同一实现/基线设置。O 四项按发现规模→比较资源→机制解释→干预排列，不是每项都重复性能数字。I B1 较长因为还担负真实影响，B3 两句分开现象与解释；长度从责任产生，无通用配额。

## 整篇引言的因果与信息分配
链条是资产价值→已有攻击/措施→跨平台未知→测量结果→防御权衡→为何失败→机制指导干预。每个 RQ 段给问题、工作及先行结果，读者无需把四个未回答的问题缓存到结尾。贡献列表因此可以删去大部分数值，改为目录式承诺。代价是引言方法结果密度高，需对 benchmark、测量和白盒机制区分清楚；不能迁移成所有论文都应有四问。

## 重新打开结果池，而非只复述赢家
可选材料包括各平台81–93.5%的泄露率、52%泄露应用含防御指令、功能逻辑与密钥等不同暴露比例、现有方法四指标、注意力及首token分布、logit分析、AREA四指标/TF1、优化耗时、模型规模、三应用、多轮及自适应攻击、消融。引言选择超过八成、33%以上平均可用性提升、约3倍优化提速，是用频率建立必要性、用功能和成本建立方案价值。若改报最低泄露相似度，会遮蔽 SysVec 在部分设置更低的事实；若把全部暴露类别塞入，读者会误以为论文中心是数据分类。对于部署判断，白盒要求、模型/基准范围、每系统提示离线优化、指标中 LLM 评审及语义相似度偏差必须随结论保留。三应用结果须连同 P7.S6 的 AgentScope 硬提示映射及基线范围理解；它既不是六商业平台的部署验证，也不包含与 SysVec 的案例比较。

## 少量保义编辑选项（非原文、非收益验证）
1. 可把 P3 的原因压入范围句：“现有评测多集中于单一平台，尚难覆盖底模和应用形态的差异。”更短、连接更直接，但少了先承认旧研究再解释限制的停顿，适合篇幅紧而非需详细综述时。
2. 可将 P7.S5 拆成保护结果与部署收益两句。先交代相对基线的保护比较，再处理功能与优化成本收益；两种结果责任更分明但字数更长，且容易把主次误读为两项独立胜利。
3. 机制谨慎版本可说“这些观察支持以注意力重锚为干预方向”。与本文观察证据相配，但不能直接冒充作者已采用的表述，也不意味着所有机制论文必须弱化因果语气。

迁移条件：适合测量→解释→系统的连续研究。反例：若机制没有指导方法，硬接四问只会把独立项目包装成因果；若新任务预设的可接受泄露条件未满足，较高可用性不能替代该条件；这是迁移到新任务时的判断，不代表原论文预设并通过了绝对安全门槛。
