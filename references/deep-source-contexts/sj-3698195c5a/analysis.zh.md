# MINER增补：让“能执行的长序列”成为找错价值的解释链

本稿与 baseline-analysis.zh.md、baseline-clauses.zh.md 中的完整重建配套阅读。旧稿已经有完整Introduction、两贡献的内容、三设计与两根因不对称、在线训练边界和正文结果池；这些都保留。本轮只深化尚未明确的作者选择和纠正局部外推。23个枢纽是选择性细读，不代表其余单元缺失，也不以条数说明写作质量。

指定源为[MINER: A Hybrid Data-Driven Approach for REST API Fuzzing，arXiv:2303.02545v1](https://arxiv.org/pdf/2303.02545v1)，2023年3月5日，19物理页；Introduction完整位于pp.1–2。这里讨论指定版本的文字与证据，不以正式会议版或当前项目状态覆盖它。来源身份与版本见检索元数据；科学适用边界集中在 evidence.zh.md。

## 先建立什么工作才有价值，再给技术成绩

MINER的任务不是单独生成一个格式合法的请求。应用需要让多个请求依次建立和改变资源状态，才有机会触及依赖复杂逻辑的错误。作者在P1最后把错误访问接到服务失效、权限和数据后果，使研究价值脱离“云服务增长”这种一般背景。语法上后果位于补充关系从句；论述上它却是这一段最重要的落点。不能以“主句重要、从句只是旧背景”解释该句。

P2的较长流程说明因此有任务。它先区分序列模板与模板内请求生成，再解释检查、状态行为、响应推断、错误序列留存。读者掌握这个过程后，才能理解为什么后文既报请求通过率，又报长序列执行分配。这是面向不了解状态式API测试的读者的篇幅选择；对专家可缩短响应分类的教学，但仍需保留“检查门槛→状态行为→反馈留存”的连接。删成“fuzzing很有效”会破坏后文指标的意义。

P3.S1的矩阵是作者的发现，具体瓶颈在that补语；P3.S2用更短的因果句立即把长链困难转为深层错误难发现。短句负责说明损失，后面的实例和原因负责展开支撑。作者还保留“不能高效生成”这一范围，没有写成“完全不能生成”。第三句给错误类别和最低请求长度，使“长”在此处有任务参照，而不只是追求越长越好。

以上源文顺序是可观察事实；“这些句子帮助读者赋予指标价值”是依据前后依赖作出的编辑解释，不是声称读到了作者心理。

## 两层障碍共同解释一条工作链，但并非同义重复

第一层是保留与扩展已有模板，第二层是给请求决定参数及其取值。P3.S7先说模板被反复放弃、从空重启，再用结果分词给长链困难；P3.S9用which和what两个疑问补语，把缺少的知识具体到参数选择和值选择。原文or连接两种不能决定的问题，转述不必擅改为其他逻辑形式。

对应的设计也有具体对象。P4.S3不是泛说“利用历史”，而是让过去成功生成且通过检查的请求序列成为可继续延长的起点。其whose从句在标点和句法上是补充关系从句，在论证上却给出这类历史值得复用的资格。概率选择再把预算偏向长模板。第二设计将历史粒度换到参数和值，学习它们之间的关系，生成多样而合意的组合。句末从组合接到高质量请求，再接到通过检查与状态探索，才把模型选择变成应用能力。

旧稿已正确把注意力模型理解为请求内参数组合学习。正文§3.2–3.4进一步说明它主要帮助前缀请求建立正常状态，最后请求保留传统生成；这支持“可靠到达与尝试异常需要分工”的解释。它不意味着本方法已经学习整个请求序列的跨请求关系，后者在§6.1仍被列为数据不足下的未来方向。无需把GRU参数、训练算法或执行步骤全搬进引言：在这里最有用的是学习对象与测试职责。

旧profile把消融解释为两个上游瓶颈“缺一不可”，力度过强。正文显示长度偏向可能提高通过率，却未在多数试验中独自改善找错；请求生成还影响较难模板及多样性。恰当的写作归纳是：两设计能对不同环节产生互补作用，所选证据要区分门槛改善和最终找错。不是由若干组合比较推出每项设计都是所有场景的必要条件。

## 第三设计增加错误类别，不能强排成第三个对称根因

参数违规checker在P4.S6分号之后才以独立设计身份进入，B1.S1再把无法发现参数误用错误写成贡献层的发现。P3对这一缺口的铺垫明显少于前两个生成问题。保留这种不对称，比替原文虚构三个已充分展开的挑战更准确。

从任务上看，前两项改善长链生成条件，第三项扩展可探查的错误类别；从整合上看，三项复用采集过程中的不同历史材料。P4末句先以兼容和协作收束方法，正文§3.4再用数据流解释共享与分工。这一收束句是系统主张，不是超加性收益的证明。把它改成“协同增益已得到证明”会增加源文没有给出的科学力度。

如果另一篇稿件需要更顺滑地预告第三设计，可以在问题段增加其错误类别缺口，但那是改变信息布局的完整编辑方案。它会占用篇幅、提前披露第三项，并必须有相应证据；不能将它称为局部同义替换，也不能说MINER原引言已经这样写了。

## 方法之后先回答数据从哪里来，结果再按读者依赖落地

P5.S1–S3由短句暂时退出技术细节：通用框架、不需事前训练语料、自动在线收集、可适用于多数REST API fuzzers及同条件改善的主张。随后给RESTler原型和三服务、11 API的实际比较范围。作者先提出框架级适用性，再给具体实现；忠实分析应保留两种范围，不把广泛主张悄悄收窄成实验已证内容，也不把原型实证扩为多数工具都已验证。

尤其要看语法与信息位置的不同。S1的矩阵只是方法等于通用框架，启动数据条件在关系从句，却是该处采用顾虑的前景。S3的适用谓语带can，而improves是另一个直接断言；转述时可明确这是作者主张，但不能无标记地把后者改为may improve。

设计顺序先序列、后请求，结果顺序却先请求通过、再较长序列的执行分配、最后可复现错误。这个顺序是源文观察；把它解释成“先过门槛，再形成较长状态路径，最终发现可分析错误”的读者路径，是编辑推断。前述流程使该顺序可读，不需要每句重新讲原理。

S6把比较数值放矩阵，把作者对请求生成改善的解释放which从句；两者都提供新内容。S7的矩阵是评估显示，that内给改善判断，which内给实际分配行为。大多数修饰的是执行次数，不是不同序列对象或覆盖状态数量。S8用可复现错误收束，再用including给安全子类；后者是包含关系，不是另加五个样本。末句选择可复现成果，能让读者联系后续错误分析和修复；这项选择价值是编辑解释，不能当成作者自述为何弃用其他数字。

“通过”“较长”“可复现”承担不同证据职责。通过率解释请求生成门槛；分配解释测试实际花在什么长度上；可复现错误说明终端成果；已删除资源子类恢复安全价值。覆盖、已知错误、组件分析与开销留给贡献及正文。更多数字并不必然让引言更好，关键是每个数字让读者多判断哪件事情。

## 两条贡献保留两类研究交付，长度由内容职责决定

B1先给问题发现，再用一个较长句概括新方案与三个新颖设计。三项-ing解释designs，是三个非限定并列项，不是三个有限主句。它们在P4已出现，贡献列表新增的是研究身份和可检视的交付边界，不能把重述算作技术首次披露。新方案、新颖设计的词也不能在“去夸张”的名义下悄悄删掉；归属清楚与科学审查分开处理。

B2四句依次承担总体性能、外部已知错误真值、设计贡献、覆盖/开销/分布。真实发现与已知错误复现不是相互替代的结果：前者给新增成果，后者允许针对外部定义的目标判断能力。逐步分析主要回答前两个生成设计的作用；checker另由正文§4的MINER_PART与MINER比较承担验证，并非三项都在同一组消融中重做。最后的较高覆盖、较低开销和多样执行分布，补全探索范围与采用代价。短的归因句用分析本身作主语，长的末句用三个并列结果压缩评价范围。均不是“越短越高级”或“一个模块一条贡献”的固定格式。

这里保留原两条贡献，而不为凑常见三条形式拆分。若因版面必须压缩，应先判断读者已从P5知道什么，再决定是否删重复总体数值；不能把外部真值、组件贡献和使用代价合成空泛的“广泛实验有效”。

## 句子跨度、替换类型与使用条件

旧账本的S是分析坐标，不能统一当语法句号计数。P2.S4与S5跨同一分号句，P3.S7与S8也如此；反过来，P2.S10、P4.S4、P4.S6单个分析单元就包含多个有限矩阵。编号转场、句法完整性和段落任务是三个层次。长句有时用于关系展开，有时只因为两个设计在分号处接续；分析长度必须先分清这两种情况。

choices.zh.md 保留每个选中单元的旧条目，并分别列矩阵、论述前景、首次新信息、上下文依据、常规形式、长度职责和读者推论。英文局部备选绑定精确源跨度哈希和词数；中文完整变体另外说明句号拆分、归属显化、关系显化等编辑成本。局部跨度不得只替动词一半，却偷偷移动宾语或删外部标点。

若词汇变化没有实质读者路径收益，就标成中性选择。P5.S6把indicates换成suggests明确列作推断力度降低的反事实，不是忠实替换；该行完整变体仍保留原作者力度。B2.S3的demonstrates选项也标为语境相关的评价力度变化，不能当作无条件保义；这里不建立show与demonstrate的普遍等级。其他新颖性、量词、can/cannot、比较对象及包含关系，也不能在语感优化中丢失。替换选择是条件化的编辑建议，不是经读者实验验证的写作改善。

P4.S5承接紧前设计标题：模型名称已在S4出现，S5新增构建动作、先进性定位和学习目的。相对长度以具体邻句比较，不说段尾整合句短于所有细节句。补充/非限制性关系从句与非限定动词结构也分别命名，避免将是否限定指称和是否具有有限谓语混为一谈。
