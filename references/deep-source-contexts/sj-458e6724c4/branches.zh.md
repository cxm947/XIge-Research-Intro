# 七组条件化生成选择

这些是基于Waltzz完整引言及必要正文回查形成的编辑决策，不是论文存在的多版原稿，不是纪守领个人意图，也不是同义句清单。各组选项改变此处要讲什么、先让读者知道什么或把解释放哪里；先按实际材料选择，随后才做保义句式转换。每组给出源观察、可执行选择、代价和本轮增量。

## G1 背景入口：先介绍技术，还是先让读者理解它承担哪项任务？

源观察：P1用计算负载→Wasm格式→编译模块实例建立用途；P2再引宿主和安全任务。属性、现实用途与风险并非另开三个宣传段。

1. 当受众不熟程序格式或其产物：选“真实计算任务→现有执行条件→产物怎么被产生／运行”。保一个输入→模块→运行的小例，像P1.S4–5所做。操作：只写后文会作为测试输入的产物和必要转换。代价：背景较长，但读者不必猜被测输入；若例子与后文无接口，只增加枝节
2. 当受众熟悉格式，但不了解为何要测runtime：直接选“运行环境保护职责→实现失效后果→检测任务”。回收P2.S1、S5–7，压掉平台历史。代价：适合专业读者，跨领域读者可能不知模块来自哪里；不可压到只剩安全重要
3. 当研究横跨旧／新部署场景，且适用范围本身重要：选“原场景→新增承载者→共享的安全依赖”。像P2.S2–3先保对象变化，再引测试需求。代价：更快解释混合评价对象，但不足以单独说明威胁，需要至少一个实际后果
4. 当现实采用价值被质疑：选一项能被资料支持的实际使用价值，并保其操作来源；若强调近原生执行，就说明应用在何处执行。代价：有外部事实核查负担，且不能把应用执行效率转写为本文fuzzer速度

本轮增量：旧卡集中于有效性和探索，此组补P1/P2入口的不同职责及性能词义分层；“任务价值先于形容词”本身是既有原则。

## G2 必要背景：什么时候值得介绍两类已有路线？

源观察：P3的变异／生成分类分别被P5／P6消费；AFL和wasm-smith已有成果被承认。P4不承担完整gap综述。

1. 当后续困难分别来自不同输入来源：选“每类最小定义＋一项真实能力”，随后在各挑战里只回收该定义。操作：变异交已有种子，生成交规则与产物，各不超过理解困难所需的性质。代价：背景会多一组对称句，但挑战段不用重复教材知识
2. 当读者已熟悉分类、只缺目标领域的强已有答案：不再给通用taxonomy，选一个能满足部分需求的工具及它的实际前提。操作：先说明合法生成已做到，再讲在当前预算里哪些组合仍难出现。代价：更紧凑，对一般读者需补一句输入来源；不能把强对照简化成无反馈弱版本
3. 当当前任务只涉及一种路线：集中解释那条路线的操作与剩余，另一类只在足以推翻gap时出现。代价：主线直接，但必须做过强近邻核查；“与我方法不同”不构成省略的理由
4. 当方案将组合已有路线：先选各自能保住的能力和各自缺的关系，再用共同任务说明为何组合。代价：要写清接口，不能以“兼顾两者优点”代替机制；已有自然组合若已解决问题，应更新gap

本轮增量：完整句图表明P3实例不仅证明采用，还预置P5/P6的解释词汇；旧卡的公平近邻原则本身不新。

## G3 挑战内容：入口条件、探索广度和运行成本怎样分工？

源观察：P5说明有效性门槛；P6开头给固定时间，再谈组合空间；两者不能用“效率不足”合并。

1. 当无效候选会在目标阶段之前被拒：选“前置检查→后续任务→当前变换为什么破坏检查”。操作：把被阻止的实例化／执行写出，挑战名用缺的能力。代价：要给必要顺序关系；只保类型名无法解释任务价值
2. 当候选已通过检查但探索集中在少数构造：选“已有有效能力→组合偏向／缺少来源→有限时间内探索不足”。操作：用一个实际先决状态说明某类构造为什么少出现，而非凭指令数量喊空间巨大。代价：多交一层偏向机制，收益是保持与入口困难的独立性
3. 当端到端测试预算是唯一可靠投入证据：选“给定运行期内的覆盖／缺陷发现”，不展开未测单例耗时。操作：将结果与同一预算和对照绑定。代价：能说明任务产出，却不能回答哪一处理阶段更快；不因缺分项成本而否认成立的固定预算收益
4. 当实际新稿确有生成／插桩／人工开销且它改变部署可行性：另选“某项必要步骤消耗什么资源→使任务少完成多少／不可部署”。需要新稿自己的对应测量。代价：可能需要额外评价和设计解释；Waltzz此轮材料不足以支持该分支的实证数值，不能借用其100%有效率

本轮增量：固定预算效率与生成速度／人力投入的分工有了P6.S1及三个不同实验的精确回查；入口／组合分离是旧卡已有内容。

## G4 设计观察：保持不变为什么能带来更多探索？

源观察：P7.S2–4与C1把栈兼容作为共同原则；§4.1明确值可改变，累计栈类型效果匹配使后续仍能取到预期类型。

1. 当可修改对象有稳定外部接口、内部实现可变：选“保接口→换内部行为→维持后续消费条件”。操作：写清哪个输入／输出类型关系固定，什么操作仍可改变，再命名变换。代价：需定义接口对象，不能把它泛称语义保持
2. 当读者更关心修改后如何继续执行：先选“后续动作仍需什么→修改须保哪项关系→据此选替换”。代价：把设计从应用需求推出来更直接，但技术名后移；兼容性条件不能随名称一起延后到读者猜不出的地方
3. 当多个模块共享同一约束：选“一个共同原则→按任务维度归组不同操作”。像P7.S4–5先立原则，再交控制／数据流。代价：减少算子清单，但贡献间界线需以所得能力说明，不能只写协同、统一框架
4. 当不同上下文改变接口所需条件：选“共同不变量＋本地上下文修正”，不要声称接口兼容独立保证所有有效性。操作：引言只交决定理解的关系，具体label／global等放方法。代价：多一个条件短语可避免假保证；不是把方法章所有例外搬入引言

本轮增量：旧卡有“栈兼容非结果等价”，本轮补出这一原则在P7与C1中的组织层级，以及主句／条件从句之间如何保值。

## G5 补充生成：已有变异之后为什么还要另一条构造路线？

源观察：P7.S5–6先给两类流的变异，再以种子里少见片段解释骨架生成；§4.4进一步交控制骨架与目标结果类型的关系。

1. 当可复用素材足够多、主要障碍是重组方式：选“怎样在共同有效性下交换／改动现有片段”。代价：机制短而直接，但仅凭重组不能断言已补齐少见构造，须依据实际变换及证据判断；若无证据需要额外生成，不为了模块数增加一条路线
2. 当已有语料缺某类关键构造：选“当前来源中少见什么→直接构造该对象→如何嵌回有效接口”。操作：让生成器的价值落到缺的产物，参照集合保持为现有种子。代价：需要一项资料或个案支持稀有性，不能将少见改为从未出现或全新
3. 当同时满足结构与类型约束是构造难点：选“先规划结构和各部分责任→再满足对应类型需求”。像§4.4的目标类型分配。代价：多交一个中间产物和依赖，但能解释分解为何可用；仅说分离控制／数据流不足以让人判断协调关系
4. 当读者只需总体方案、后文已有详细构造：选“对两类流的变异＋补充种子中少见构造”，把递归、最大深度和上下文更新留后。代价：引言更轻，但至少保所补产物与已有策略的关系；不能只剩算法名称

本轮增量：本源历史卡有骨架生成与少见片段；本轮补分解的真实接口和两处可用解释深度，不把方法细节全前移。

## G6 代表证据：哪项结果最值得进入这句？

源观察：P8/C3同时报告覆盖、独特bug、新bug、确认与编号；完整核对表显示这些回答不同问题，统计集合并不相同。

1. 当评价主判断是找到更多runtime缺陷：优先选同预算总量对照Table2的33对24，可换算多37.5%；若突出实际新产物，再加20个新bug均确认。代价：直接回答终端任务，但不能解释效果来自哪一机制，也不能声称所有目标均赢
2. 当前文核心承诺是更有效探索程序行为：选边覆盖及其同预算对照。若用12.4%，只作为源报告汇总，不替它补七目标平均；若需要可明确定位实例，可选SpiderMonkey多17.4%并标实例。代价：代理更贴探索论证，但不是最终缺陷数；不能为了更大数字改用扣初始seed的94.4%并暗换分母
3. 当需要确认关键原则确实能产出可接受输入：选三个JS引擎24小时试验中定制路径的100%有效率和有效样本数。代价：解释入口能力很清楚，却不能替代72小时全部目标的发现结果，也不证明全管线吞吐
4. 当读者已接受量化效果、还需理解新增构造为何有用：选§6.5一个有代表性的实际缺陷案例，写构造特征、旧路线难点和实际维护／利用风险状态。代价：可解释模块如何协作，但个案不是生成器总体因果消融，潜在可利用不等于已成功利用

本轮增量：比值、实验时间、统计路径和确认子集均有可审坐标；“先任务再证据”的原则原本已有。对于本源的紧凑迁移，能清楚核对的bug比较／确认事实优先于未明汇总口径的大数，不是放弃正面结果。

## G7 方案、预告与贡献：重复多少取决于前面完成了什么

源观察：P7已解释策略，P8完整预告结果，C1–C3再归纳方法与评价，P10另交开放资源。三个贡献按研究所得归组，不按算子数量列项。

1. 当目标稿已有独立方案段，而且按作者框架方案后直接接贡献：保P7式总体交付与理由，将P8的任务结果／确认状态放最终评价贡献；不另加一段完整预告。代价：贡献的结果项会比源C3更承担首次解释，不能照源55词机械限长
2. 当稿件允许结果预告且读者需先看收益再扫贡献：用独立结果段交范围、代表结果和状态；贡献聚焦成果归组并保能独立理解的核心事实。代价：必要重复仍存在，必须检查每次重现的职责，不能复制所有数字以凑完整
3. 当方案机制已十分简短、贡献承担首次解释：非评价贡献可保“能力＋关键关系＋产物”，必要时比本源C1/C2更长。代价：列表阅读负担增加；不能一面省掉方案说明，一面以去重为由再删贡献内的唯一原理
4. 当多组件仅共同形成一个推进：按共同保持原则、探索扩展、评价所得归组；资源发布放末句或真实独立资源贡献。代价：减少表面贡献数，但使每项有独立任务含义；代码公开本身没有独立研究价值时，不为四项惯例强设贡献

本轮增量：原技能已有“篇幅由解释职责决定”；本轮给出50句全章内P7/P8/C1–C3/P10的具体责任移动路径，可直接用来决定保、移、压，而非只再说一次不重复。

## 固定命题后的三组保义表达选择（不计作以上内容分支）

以下为本轮编辑新例，不是原文引句。每组三式保持事实、模态和统计范围；变化只是焦点与读取负担。实际成稿通常选一句，不同时展示三句。

### L-A 固定命题：当前测试目标须先接受有效模块，之后才能实例化和执行

- 焦点在任务后果：未通过有效性检查的模块无法进入runtime的实例化与执行阶段
- 焦点在规则：runtime先检查模块有效性，再允许通过检查的模块实例化和执行
- 焦点在前后依赖：要测试实例化和执行阶段，输入模块必须先通过runtime的有效性检查

选择与代价：第一式适合刚谈无效变异；第二式适合首次解释流程；第三式适合连接应用任务。第三式明确当前要测的阶段，不能扩为整个runtime的所有测试都需要有效输入。

### L-B 固定命题：在所讨论的栈类型条件下，兼容的序列可互换而保持后续所需类型

- 焦点在可改动作：可以替换指令序列，只要替换前后与后续计算所需的栈类型关系兼容
- 焦点在不变量：保持后续计算所需的栈类型关系，便为指令序列的兼容替换提供条件
- 焦点在读者分步理解：替换必须保留后续计算需要的栈类型关系。在这一条件下，序列内部的具体操作仍可改变

选择与代价：第一式使允许变化更醒目；第二式让保持原则适合统领多个模块；第三式适合首次介绍不变量的读者，多一回指但避免把保持误读为不改变行为。其他上下文有效条件已在该段明确时可省重复；未明确时必须补，不把类型关系单独写成任意程序合法性的充分条件。

### L-C 固定命题：主比较中Waltzz共找到33个独特bug，AFL++找到24个

- 直接对象先行：在该固定预算比较中，Waltzz找到了33个独特bug，AFL++为24个
- 任务比较先行：在该比较中，Waltzz比AFL++多发现37.5%的独特bug，即33个对24个
- 总量比例先行：该比较中Waltzz发现的独特bug总量约为AFL++的1.38倍，分别为33个和24个

选择与代价：直接计数最容易检查；百分比突出新增产出；总量比例适合沿用源摘要习惯但必须明确是总量。三式不改成20个新bug的倍数，也不补成每次平均或每个目标均提高。
