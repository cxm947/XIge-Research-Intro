# CPscan：用“被删了”与“仍有必要”两个判断组织整篇引言

2026-10-05重新读取[共著者托管CCS2021排版PDF](https://www-users.cse.umn.edu/~kjlu/papers/cpscan.pdf)，17页，794–810，SHA-256 3bbfeca53b32323a4e114be47d57fe8b254e497224a3453f9ef5bb4ec564b382。不声明它与另取ACM VOR逐字/字节相同。完整§1 pp.1–3，并读§2范围、§3.2–3.4设计、§4实现、§5检测/比较/误差及§6限制；渲染pp.2–3、10，核对表图引起的抽取顺序。归纳为共著论文的研究/表达选择。

## 先建立正确判据

任务是检测下游IoT内核裁剪Linux代码时引入的新安全缺陷，研究对象是删除的安全操作DSO：检查、初始化、资源释放。CPscan需要下游及对应上游源码；目标不是全部代码差异，也不是恶意厂商刻意隐藏后门。大多数删减本来合理，删除操作是否危险要看其保护的变量和后续用途是否仍存在。

已有0-day缺陷检测器能发现特定缺失检查/初始化/释放，但常需相似代码交叉参照或有较大代价；N-day相似度检索依赖已知漏洞，而裁剪会产生新漏洞。任务可自然拆两步：精确定位DSO，再判安全影响。第一步不能只给函数相似分；第二步不能把所有删除都报漏洞。

方法先以安全操作等区分属性建立高置信基本块种子，再按已配块邻居迭代结构匹配。安全影响推断先排除合法补丁/代码封装，找删除操作保护的变量、对应变量及相同来源，只比较潜在受影响区域内的用途。若这些有界使用链保留，原保护仍可能必要。这是保守风险启发式，不是删除必可利用的充分数学证明；人工确认仍需检查行为逻辑与可达性。

## 段落设计与同一例子的连续职责

P1三句（p.1右）内核作用→自研成本→Linux复用。P2十二句（跨pp.1–2）先给定制及省资源理由、规模、承认大多数合理，然后才错误删除与三类风险。图1空指针检查例解释原操作职责、删除后错误状态，最后回收设备影响及检测需求。承认合理裁剪不是礼貌话，是给后面必要性判断建立正确任务边界。

P3九句从直接用现有检测器出发，承认真实能力，分别说明0-day条件、cross-check参照、Hector范围、N-day已知漏洞条件。这个逐层比较比泛称“传统方法效果差”更具判别力：新的研究价值是已有来源参照可用而下游用途仍相同，改变了可以比较的对象。

P4十二句先明确两判断，再用同一图1说先定位再分析影响；后续按输出要求检查相似分工具、文本diff、AST、LLVM IR。比较的焦点是结构变化下精确删除，而不只是哪个算法更现代。P5七个主句结构加四个问题子单元，先说删除可合理，再问变量是谁、还在吗、在哪里怎样用、可能何种错误状态。读者由这些具体信息缺口理解语义推断为何难。

P6十五句为第一步方法：选图匹配因为兼顾结构语义，但不假定选择技术名就解决问题；已有图算法仅完全块且复杂度高，作者人工看两个内核后得到“安全操作可区分种子”“邻接已配块者更可能对应”两观察，再交ACFG、初匹配、邻居迭代。该长段有观察→机制的必要桥，可以分段提高浏览，但不宜剪只剩新图匹配名称。

P7七句为第二步：提出不一致比较，定义有界使用链，给用途保留→保护可能必要的条件推理，再回图1检查用途没变、原NULL防护仍需。一个例子先定义问题、再固定子任务、最后验证方法前提，避免每段引新代码给读者重置上下文。

P8九句从LLVM/28内核/10厂商/9小时到定位精度85%、图匹配提速400倍，再给3193DSO→359候选→114人工真缺陷→10开发者确认；最后长潜伏及危害。每数属于不同证据层，不能把定位精度套到最终报告。P9引导及三贡献将已展开信息重组为认识、技术、系统验证。

## 完整贡献集合

C1两句：大规模裁剪研究和具体误删类型。C2两句分别定位技术、影响推断；两个动作对应两判断，而非两个模块各自无关系。C3三句：实现首个系统、实际114发现及范围、后果。标题“综合评估”包含系统产物和现实发现，并非纯统计条目；写作分类不需要强迫科学句完全互斥。

C3重复114是保留可独立阅读的成果锚点，但不重复全部过程数字，因为P8已经校准错误率及确认层次。若只读列表容易把“可靠”理解成高报告精度，所以系统卡必须与前段数据联读。原文“影响数十亿设备”为厂商/生态规模的广义影响主张，本轮未见按每缺陷部署量核算，不能改成114漏洞全部都存在于数十亿在用设备。

## 正文数字池及选择的适用强度

表4 p.10：八个手工标注内核定位DSO平均precision85.4%、recall94.9%，GumTree的DSO召回66%、两个LLVM差分11%。不同工具目标不同：基线找所有删除，CPscan只找安全删除，作者因此在合成集按各自任务评精确/召回，在真实集比较DSO召回。引言85%是定位阶段，不是最终漏洞精度。

表5：CPscan4.05秒/文件，GumTree3.06、LLVM-Diff0.93、归一化版0.99；400倍只对最接近图匹配McGregor，不是比所有工具快。这个选择回应“高复杂度图匹配能否落地”，不能移成全系统总提速。

表7/§5.4：3193项删除中自动报告359，人工确认114；245/359约68%是假阳性。三研究者约38人时确认，其中10项又获开发者接受（论文当时状态）。论文也给局部缺失检查比较58.3%假阳性、表6抽样推断precision38%；这些是不同子集和阶段，不能挑85%掩掉真实筛查负担。引言展示候选→人工→厂商链，比一个总“高精度”更可判断。

四个合成内核中人为删除700处安全操作（261处检查、214处初始化、225处释放），构造700个缺陷实例；检测到424个，漏掉276个，召回约60%，不是700种删除类型。真实抽样召回约67%。在这276个合成漏报的原因分析中，40%归于使用链改变后仍可能有bug。§6.1源文明示，相同有界使用链的保守判据旨在减少误报，但因此漏掉用途改变后仍有缺陷的情况，构成误报与漏报的技术取舍。该条件式判据也便于解释推理过程，这是另一个编辑观察，不能替代作者明示的降低误报理由。误报中代码重实现36%、错误匹配51%，说明先定位再推断的两个步骤都会影响终端效果。

原始代码覆盖仅约45%定制源文件、60%定制函数，因架构/编译配置/LLVM兼容。9小时是已编译、纳入的74,542定制函数分析，不是所有28内核每一文件穷尽。与Crix/PeX比较也以缺失检查子任务、有限时间预算进行，作者明示工具互补。

潜伏最长9年5个月可说明常规维护没消掉问题，但不是所有缺陷平均年龄。若新引言重部署，应选确认负担和代码覆盖；若重比较技术，则选定位精召/耗时；若重问题发现，则选误删类型、潜伏及新发现。不同证据改变文章重点，不能把最大数自动当最好数。

## 保义表达选择

原创编辑选项，非源句引用或效果已证。

P5必要性A：Deleting a security operation is not necessarily a bug: the protected code may no longer need it after customization.
B：A security operation can be removed legitimately when customization eliminates the need for the protection it provided.
A先修正误推，B先给合理条件。均保留“有些删除合理”，不声称所有下游定制安全。

P7判据A：If a security-critical variable retains the same uses within the operation's affected region, the original protection is likely still needed.
B：The original protection is likely still necessary when the associated variable's uses remain unchanged within the code region it affects.
同样保留关联变量、有界范围、用途相同、可能必要四条件；A从观测推结论，B先结论再条件。不能删likely变成完备漏洞判据。

改变信息选择：用“359报告、114人工确认”替换“85%精度”会把焦点从定位子技术转为端到端排查工作；两者不是同指标的表达变体。可迁移写作操作是先分清研究中的不同判断和不同证据集合，让每个方法及数字只回答它能回答的问题。
