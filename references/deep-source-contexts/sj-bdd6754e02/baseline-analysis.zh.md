## 任务、近邻与证据
任务是在有限时间内发现提交新引入的错误，不是最快覆盖一个指定位置。覆盖式模糊测试已有发现真实漏洞的能力；定向方法又能优先到达改动位置；最接近的不足发生在到达之后以及多目标之间。改动点与崩溃点可以分离，保持到达条件的同时还要探索其他输入状态。WAFLGo 的控制流前缀与数据依赖后缀，分别覆盖怎样到达、影响向哪里传播；变异掩码保留所需执行，稀有边与不同能量分配恢复多样性。多目标距离与支配树合并不是第三个随意模块，而是防止单目标策略被汇总稀释，并利用同提交共享前置条件。

表1的30个历史缺陷里21个属于位置不同、9个相同，支持任务现象存在且在此样本占多数，不是所有 GitHub 提交的总体频率。评测为8类/个被测 C 程序集合中的30个缺陷，8个对比工具，24小时、五次重复，超时按24小时进入提速计算；10.3倍必须带该聚合规则。正文报告复现21个缺陷，并对最新50次提交进行新缺陷实验，发现7个其中4个CVE。§5讨论仍有超过12小时的案例，不能把均值收益翻译为实时CI保证。

相邻口径与定位资格：源作者单位为八个C程序。§6.1/Table3的提速比较只覆盖21个已复现案例，比较工具超时按24小时计入；21/30才是完整30案例集合的成功分母，不能把10.3倍称为全30案例的平均。超过12小时的讨论实际在§7（物理pp12–13），上段§5是保留分析的定位错误。

## 跨尺度选择、结果池与保义变体
全引言先给合理最近解，再用错误位置和多个相互关联位置两种任务事实修正目标。两挑战来自本文工作分解，不可提炼为所有论文必须恰好两挑战。P6显著长于其他方法概述，因为掩码与两阶段选边若不解释，保持执行与增加多样性看似冲突。正文还提供到达时间/首次崩溃差、前后缀覆盖、路径多样、消融、开销、合并目标及新漏洞。选10.3倍、最多复现、7/4分别覆盖效率、有效性、现实增量；只报到达时间会重犯论文指出的代理错位，只报新CVE数则无法隔离历史样本差异。均值不是每例提升，静态依赖质量与C工具链限定适用范围。

编辑选项而非原句：①“改动点只是探索入口，错误可能在其数据依赖后续暴露”可代P3多个解释句，短且突出传播，但失去频率和两类旧方法冲突证据。②把P6分成到达前/到达后两短段，更易模拟状态机，代价是弱化统一的关键代码不变量。③结果先写21/30及预算，再写聚合提速，更可审计但需要多一句协议。适合读者关心CI预算；不代表普遍更好。
