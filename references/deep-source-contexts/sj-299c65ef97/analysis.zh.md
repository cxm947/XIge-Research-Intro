# DEEPSEC：把评价资源写成可用的判断能力

## 阅读身份与边界

本文是指定源 `sj-299c65ef97` 的写作分析，源为[实验室托管18页稿](https://nesa.zju.edu.cn/download/DEEPSEC%20A%20Uniform%20Platform%20for%20Security%20Analysis%20of%20Deep%20Learning%20Model.pdf)。标题末词为单数 Model，无可见论文集页码。完整Introduction位于物理第1–2页。共同署名、版本指纹和实际阅读范围见 `source-coordinates.json`。P/S/C编号沿用完整图，是分析坐标，不是论文印刷编号。完整图含35个分析单元，其中34个P/C/R单元已登记默认单元路由；END-S1为图内可读的终结导航，未登记单元路由。未运行任何模型、攻击或代码实现。

以下严格区分三类内容：
- **源观察**：指定版本可直接看到的内容、措辞结构与结果报告
- **编辑解释**：这些选择怎样帮助读者理解或作出判断，不等同作者自述意图
- **迁移操作**：换到新稿时需要什么事实、应选什么内容和表达；不借源论文为新稿提供研究事实

本文并不将DEEPSEC的历史实验结论当作已独立验证的科学事实。针对该工作的公开批评仅用于标明必要证据边界，详见 `evidence.zh.md`；研究受批评不取消可观察的写作组织价值。

## 1. 先理解研究：用户缺的是什么判断

**源观察｜P1.S4→P2.S1→P4.S3；§III-A，物理pp.5–6。** 引言先交代攻击与防御各自想达到的效果，并为防御保留正常输入上的用途。随后把问题交给研究者和实践者：方法很多，但尚不清楚哪些方法在哪些方面强或弱。本文不是再提供一个独立攻击，也不是把实现数量本身当终点；它提出评价平台，让读者能够检查模型风险、评估防御、比较多种方法。

**编辑解释。** 这里的价值链不是“平台功能多，所以重要”，而是：

评价维度与比较对象变得可操作 → 原来混在一起的强弱关系能够被分开考察 → 研究者或模型使用者有机会按实际目标选择、诊断或继续研究。

这一链条也决定读者理解顺序。必须先知道攻击成功不只是一项分数、防御也有正常效用要保留，后面的“多指标”和“交叉比较”才会被读成判断能力，而不是数量宣传。任务价值与认知前提因此使用同一组事实，无须另加“有益社区”段。

**必要正文回读。** §III-A的体系将攻击产生的样本、防御产生的模型，分别送入攻击效用、防御效用及攻防交互评价。这个接口解释了为什么评价指标能在贡献中成为平台的区别。§II-D又明确，防御效用的五项指标只针对完整分类防御，检测型防御另行处理。因此，“13种防御×5项效用”不是每格都有同义观测的简单矩形。

**迁移操作。** 对平台或测量论文，先用一句普通话确认最终判断，例如“用户要知道同一工作负载下哪种策略满足准确率与延迟要求”。之后才决定需要哪些方法、哪些测试条件和哪些指标。若项目只统一了接口，尚未建立可用判断或新认识，不应把“集成了更多组件”自动升为主要研究贡献。

## 2. 完整引言的读者路径

### 2.1 P1：在提出评价缺口之前，先给评价的对象和判据

**源观察｜P1.S1–S4，物理p.1左下→右上。** 四句依次处理技术进展、对抗输入风险、风险为何引发大量攻防研究、双方各自的任务目标。S2内置定义，不让读者先带着未定义的风险名词进入gap。S3的应用列表承担风险重要性与研究活动规模；S4的攻防对称结构则第一次建立评价应保留的双重约束。

**编辑解释。** S4比开场背景更值得迁移：攻击的目的与输入变化、防御的抵抗效果与正常用途，都在一个连续句群里。后文的多维评价于是有了前提。句子并非只介绍领域，实际上已经在选择“什么性质值得量”。这也是为什么不能只留下“攻击导致误分类，防御抵挡攻击”两半句：删去扰动性质与正常效用，就会把后面的指标系统写成缺少任务理由的附加清单。

**语言与篇幅。** 本地计数为28/27/45/53词。最后两句的长度分别来自应用例子和两方任务展开；不是“高水平论文必须长句”的证据。新稿的读者若已熟悉应用场景，可以压应用列表，保住最后的任务判据。不能因P1提到医疗、恶意软件等应用，就把本文在图像分类基准上的结果说成在这些领域均已验证。

### 2.2 P2：把“方法很多”转为“选择仍不可靠”

**源观察｜P2.S1–S12，物理p.1右栏。** S1同时承认已有方法丰富和定量认识不足。接着三组原因分别涉及评价维度、对手覆盖和知识随时间变化。每组先交一般问题，再给例子或报告的观察；S9汇总认识后果，S10–S12用同一种防御在连续研究中的不同报告形成具体见证。

**编辑解释。** 三组困难属于“认识为什么不够”的不同轴，不是一个新算法的两项技术挑战。第一组告诉读者：单个高分未必回答完整任务。第二组挑战一种节省比较的捷径：用几个被称为强的对手替代整个适用范围。第三组把持续更新纳入平台需求。最后的历史例子使“可能结论混乱”变成一个可辨认的研究判断过程，但它不能证明所有早期结论都在完全相同条件下互相矛盾。

这段有两个值得同时保留的优点。其一，已有研究不是被写成一无是处；方法多恰好使评价问题有价值。其二，缺口不是泛称“不全面”，而是读者可能作出的错误推断。然而，S4/S6把本研究报告的发现提早用作动机，属于“本文观察支持需求”的写法，不应在迁移中把待验证直觉改成已证实规律。

**篇幅取舍。** 该段217词、12句，是引言最长的论证区域。长是因为承担了三类原因和一个三步历史见证。已有稿若已给可信具体例子，可以压S9式总括；若读者尚不理解为什么少量对手不够，则应补真正改变选择的反例，不能只把句子缩短。DD历史轨迹在这里比增加三个库名称更有解释价值。

### 2.3 P3：先公布平台应满足的判断条件，再宣布自己的平台

**源观察｜P3.S1–S3、R1–R4，物理p.1右下。** 总体论断后列四项要求，分别对应比较设置、代表方法覆盖、评价信息和未来扩展。随后指出现有资源尚未联合满足这些要求，细节放后文。

**编辑解释。** 这是一个对平台进行评判的标准层。读者先获得“什么样的平台才足以帮助我判断”的尺度，才遇到系统名。四条都是可展开的功能要求；它们没有被包装成四个互不重叠的新发明。三类问题和四项要求也不是一一对应：统一性支撑多种比较，覆盖性与可扩展性共同回应不断变化的方法集合。

**必须保留的逻辑强度。** P3.S3说的是没有现有工作同时满足要求，不是每个库都没有价值。两者差别决定相关工作应怎样写。真正迁移时，应保留最近资源已解决的部分，再说明本稿为什么需要这些性质共同成立；不能先任意列出恰好只有自家系统满足的属性，再把属性数量当gap证明。

**从愿望到实现的桥。** 本文引言没有细讲四条要求如何实现，§III才给出模块化、独立模块及评价接口。若新稿缺少独立方案段，应在方案处交出足以证明要求可实现的关键关系；若作者框架已有P5，就在那里补，不仿照本源省掉当前稿尚未完成的解释。

### 2.4 P4：用范围说明可用性，再用使用者的动作说明价值

**源观察｜P4.S1–S4，物理p.2左上。** S1给平台名和承接对象，S2交当前实现的覆盖规模，S3以三个使用动作交出用途，S4直接接贡献。

**编辑解释。** S2的数目回答“有什么可用”，S3回答“可用来判断什么”。二者不能互相替代。尤其S3的受益者不是泛称研究社区，而是此前P2已经出现、正面临选择困难的人。前后对象一致降低了读者将平台理解成另一套攻击方案的风险。

**词汇职责。** 当前实现的时间限定把已交付集合与未来扩展分开；能力动词把平台功能和已经完成的实证研究分开。后者要到C2才兑现。新稿若只实现了一套接口但没有进行比较，不应把“支持研究”改成“证明结论”；反过来，已完成比较也应直接写所得，不停留在“可用于”。

### 2.5 C1–C3：工具、使用工具进行的研究、由研究获得的认识

**源观察｜物理p.2左栏。** C1交平台及两个区别：方法覆盖、指标成为核心评价对象。C2交多指标研究与攻防交叉比较。C3第一次在Introduction集中交三项实质发现，最后还有缩写/符号表导航。

**编辑解释。** 贡献集合按三种不同层次组织：资源能做什么；实际怎样使用它；得到什么认识。这里的平台实现不是天然贡献，因为C1要靠比较上的区别解释其研究效用；C2也不只是“我们运行了实验”，而是试图建立此前难以观察的相对关系；C3则让读者看到平台不是只有潜在用途。

C1与P4必要重复同一资源和数目，职责却不同：P4用于认识本文交付，C1用于确认增量。新稿可压相邻重复的数字，但不能据此删去任一处尚未交出的能力。

**C3选材结构。** 三项报告分别涉及目标间的取舍、适用范围、聚合效果与薄弱处的区别。它们都改变怎么解读评价或怎样选择防御，故无需选“最大提升百分比”来证明平台价值。三项之间不是一个性能数字的三个版本。源把它们放在同一个长句内；拆成数句可提高各自边界的可见性，但不能把三句自动变成三项独立贡献。

**关键限制。** C2的指标数不能直接解释成15项从无到有的指标发明，正文有多项既有指标及引用。C3关于ensemble的措辞也比其局部数值和正文解释更绝对；表格内还有直接影响下界叙述的例外。这些具体问题见 `evidence.zh.md`，不应为了学习语言而继承其证据强度。

## 3. 四项平台要求如何变成正向选材依据

|---|---|---|---|---|---|

**编辑解释。** 这张表不是建议把四条都抄进新引言。它使属性、任务后果与读者前提在同一选材动作中完成：例如，保留评价对象的范围是为了避免用户把一个条件下的好分数当普遍强度，而不是为了让文章多一个“全面”形容词。

## 4. 评价答案应该怎样选，而不是怎样堆结果

详细核对在 `evidence.zh.md`，这里保留写作决策。

1. **先选解释某项实际判断的关系。** 若用户要知道成功率高是否足够，应选择与输入可接受性相连的证据；若用户要选择防御，应选择相关威胁范围与正常效用；若用户要决定组合策略，应同时说明比较的聚合层次与薄弱条件
2. **区别同一输入上的多轴观察和多个不相同子集的分数。** 本源多种指标只在成功攻击样本或共同正确样本上定义，数值并非都用同一分母。一个句子说“同时改善”需要共同条件的证据，不能靠相邻表列的位置
3. **把数字放回任务定义。** 表III中的CW设置比较可以展示置信度与扰动之间的变化，但两个设置的MR均为100%，不能改写成“错误率从低到高”的例子。表IX中的84%与82.2%是所报聚合比较，不能替代最坏情形安全保障
4. **对直接改变结论的反例作修订，不作装饰。** 随机ensemble的JSMA行是6%，因此正文的普遍低端描述不能原样迁移。可以学习C3把整体与薄弱处拆开的表达需求；不能将争议内容改写得更流畅后作为可靠事实传播
5. **保留确认状态。** 源C3把一个取舍称为实验确认，另两项以经验归纳交出。迁移中，已有文献现象的再确认、首次发现、新指标构造是不同成果，不因为都能放进贡献就合并成“提出新发现”

## 5. 篇幅与句式的可迁移决定

计数及完整口径见 `source-coordinates.json` 的length_statistics，只作本版本描述。Introduction正文及贡献788词；加最后符号导航为802词。共29个终结句，另有4个要求条目。P1=153，P2=217，P3整组=109，P4=91，C1/C2/C3=76/59/83。四项要求及C3内部的分析子单元不重复计数。

- P1末句53词，长度购买的是两方完整任务，不只背景修饰；压缩时优先移除已知例子，保住任务约束
- P2先用8词短句标第一原因，再以具体例子和判断后果展开；不是每一句都用同样长的平行模板
- 四项要求共46词，用排版帮助读者记住并回指四种性质；迁移为散文会省去列表占位，但可能增加回指负担
- P4共91词，资源范围和三种用途尚未交方法机制；在本文它依赖正文，在新稿若独立方案段承担机制，应增加必要关系而不照搬短度
- C1第二句59词，包含差异总括、知识范围限定、数量例证、第二特征与结果；若比较对象已在正文引入，可拆成两句并省一组数量
- C3单句83词，承担首次出现的三种研究答案；将其压到只有“得到重要发现”会删除全文引言的主要结果。适宜的缩短是去掉低信息评价词，保留三种不同关系与各自条件

这些观察不构成固定结构通则。迁移时以任务答案选择证据、按解释职责决定长度、按研究性质选择体裁。这里提供可回查的具体案例：评价标准怎样在产品之前成立；资源规模、协议、结果认识如何分工；同一表内不同分母怎样限制跨方法成句；源结论的聚合词与表格例外怎样实际改变迁移表达。六组条件分支与具体成句选择见 `branches.zh.md`。

## 6. 可迁移关系与本案例的细读价值

**可观察的组织关系：** 三类评价问题、四项平台要求、平台/比较/知识三层贡献、ensemble的范围条件。

**本案例的具体展开：**
