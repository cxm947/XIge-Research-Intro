# TextShield增补：先说明哪些语言条件让旧防御失效，再让流程和证据回应这些条件

本稿与 baseline-analysis.zh.md、baseline-clauses.zh.md 中的完整重建配套使用。原稿已完整读到Introduction末尾的第三项贡献，已有29个分析单元、中文迁移理由、三阶段流程、两类评估和正文证据边界。本轮保留这些实质内容，只深化17个枢纽的作者选择、句法信息位置及条件化编辑，并修正一个实际概念混同。数量仅界定选择范围，不用于声称写作改善。

指定源为[USENIX Security 2020正式论文](https://www.usenix.org/system/files/sec20-li-jinfeng.pdf)，题名TextShield: Robust Text Classification Based on Multimodal Embedding and Neural Machine Translation，物理19页含封面，正文印刷1381–1398。完整Introduction位于物理pp.2–3/印刷1381–1382。指定源版本及哈希见检索元数据；完整历史分析与当前资格分列。科学适用限定单列，不把这份作者选择分析改写成逐表纠错报告。

## 三个不同的“为什么需要”，不能跳成一个泛背景

P1把社交平台规模、文本危害和治理压力依次给出，再以数量与增速结束。这一段最直接支持的是自动化治理的需要，还没有证明分类器需要对抗防御。P2先承认DLTC相较人工在效率与效果上的成功，再用研究发现和具体规避现象指出：对人仍有害的文本，可以使模型判断失效。这才说明为什么有用的自动分类器还需保护。P3又承认英文防御近邻，然后解释迁移到中文的问题，才说明为什么不能只把现有措施换个语言测试集。

三层正当性分别是规模下的任务需要、现有自动系统的残余风险、旧防御依赖条件的变化。这个推进顺序可在原段落中观察；将它解释为读者逐层获得支持新方案的理由，是编辑分析，而非声称作者明确写了三层理论。

P2.S4的短句尤其关键。矩阵说攻击者可能生成文本，关系从句用but把保持毒性和逃过检测连在同一对象上。这不是两个互相替代的成功标准。读者先懂这个不变条件，才不会把“把有害文字改成无害内容”误当成真正规避。随后例子说明人类意义与模型判断的分离，白盒/黑盒定义再切换到知识条件轴。这些定义是背景知识，不自动构成后文同时验证两类防御的承诺。

## 近邻之后给失效原因，领域差异才成为方法理由

P3.S1先命名对抗训练和拼写纠错，并承认英文领域已有相当成功。它的主句报告方法已提出，补充关系从句给成功评价；成功究竟直接附着近处models还是回指防御路线，有表面附着空间，段落语境支持将其理解为近邻方法效果。分析应说明这种语境解释，而不只凭最近名词强行定指。

P3.S2较短，只标中文鲁棒研究有限。下一句很长，不是单纯把“工作少”再讲一遍，而是从研究数量转到方法条件：字符语义与字符空间、无显式词界但需词级判断、扰动稀疏而多样。冒号后三项并非三个句法同构的原因从句。第一项有语言对比、单字变化的可能性及结果；第二项用形式主语、since和while解释纠错难；第三项仍用likely保留训练后对新攻击敏感的可能性。

这种不完全对称有内容原因：一个问题关乎表示和语义变化，一个关乎纠错的判断单位，一个关乎可覆盖的扰动分布。原文明确给这些原因，但不能将它们升级为中文模型在任何环境都必然更弱，或数学上唯一推出后面三个阶段。将字形/字音表示、上下文纠错与泛化负担联系起来，是有源文基础的设计解释；逐项是否充分、是否唯一仍是另一证据问题。

紧随的具体化句将字符规模和字形/字音策略接到抽象复杂性上，括号把详细例子留给§4.3；段尾再用平台规模恢复应用分量。这样，方法出场时读者已有“为什么要解决这个条件差异”的理由。原句存在结构缺少关系连接，本包把增加关系词单列为语法修复，不教读者照抄异常句形。P1的异常形容词也保留为源问题，没有偷偷改写源记录。

## 为什么三阶段长句要保持中间对象在主题位置

P4先给具名的新框架和两类关键技术，再用短句预告三阶段。接下来的长句以输入文本、纠正后文本、提取特征依次作被动主语：每个前一阶段产物都成为后一阶段可以继续处理的对象。First、second和finally标出顺序，which从句说明多模态特征和表示就绪所带来的功能。语法上这是一条含多个有限矩阵的分号链；论述上它是同一材料沿处理过程前行。

因此，被动并非仅为“学术口吻”。这里让对象保持在句首，比连续重复“we采用了三种技术”更方便读者跟踪接口。这是具体语境下的选择，而非普遍规定方法都用被动。若读者更想知道系统动作，旧profile的过程主语A变体仍适用；若关注接口，中间对象B变体更合适。两种旧备选均保留。

第一阶段只承诺处理部分扰动。该some一方面限制NMT的工作，另一方面给后续多视角表示留下作用空间。§5.2确实报告纠错后仍有变体而组合分类仍较准确，并由作者解释部分恢复加多模态分类的可能性。因此，把两个技术理解为互补有正文依据；但不能将“纠错一两个就足够”写成所有文本的普遍保证。

方法选什么、为何适用于任务、输出怎样接到下一步，都可以在这条流程句里说明，而不必把NMT内部训练公式或字形CNN细节搬进Introduction。这里的多模态是同一文字的不同表示，不意味着另要用户上传语音或图片；NMT是中文到中文恢复。更详细的训练事实支持边界判断，放在附件即可。

## 评估预告、贡献数字与采用状态各做不同工作

P4.S4把两真实数据集的评估范围放在句首，再报告对用户混淆文本和自动攻击文本有效。句首材料先给读者判断“有效”覆盖什么的依据。四平台比较提供实际服务参照，下一句正在整合某平台则是采用进度，不能合并成已经部署且有效的同一个证据。

贡献C2与C3也不重复。C2先问真实用户混淆是否还能识别，并把普通输入条件下的效用损失放在同一个结果句；C3再问攻击过程适应防御之后是否仍稳健，同时给工业参照。选择较强自适应评估而非更小的迁移ASR作为贡献例值，能回应“攻击者知道防御怎么办”，这是编辑解释；源正文明确采用整管线黑盒自适应设置。它不是白盒或无限扰动下的最坏情况保证。

C2.S2的矩阵是结果显示，准确性和小代价在that补语及while结构中展开。从属语法位置不意味着其中的实用代价是附带旧信息。两个e.g.分别限定对抗文本准确性和普通输入性能，不是两数共享同一个样本条件。旧profile将后一数字解释为“正常文本是否一起误伤”，这里需要纠正：论文的benign inputs指未受对抗扰动的输入，常规分类数据同时包含有毒与正常两类。该准确率回答普通分类效用保留多少，不能仅凭这一值推得无害文本误报率。

C3的矩阵并列verify和compare，which再给作者对实用性/优越性的判断，括号给ASR例值。这一例值的正文比较是特定基础模型与防御配置，而非四平台降幅的平均。句子把不同证据职责压在一起，若要拆开，应按验证动作、比较范围和作者解释分开，不能把作者的强评价静默改成自己的谨慎结论，也不能反过来把评价当普遍保证。

## 贡献身份、首次性与训练措辞需要分别保留

C1的方法和技术已在P4出现；贡献句新增的是首个、专用于中文、据作者所知、无需重训及技术新颖性的明确定位。矩阵we propose只提供提案身份，后面which和in which承载大部分内容。把所有从句都缩成“提出一个防御框架”会失去作者挑选的研究增量。

两个first指向不同的新颖性对象：前者是首个专用防御身份，并带所知限定；后者在贡献中与新颖多模态方案并列，主张首次将对抗NMT用于该恢复任务。P4另用阶段词交代先纠错的流程顺序，不能将它移到C1来削弱首次采用的贡献主张。完整中文变体保留两处首次性，并明确归属于作者；本包未独立穷尽近邻验证优先性，也不把它扩成NMT史上的first ever。

“无需重训模型”在源引言中确实存在。正文又描述联合训练并说实验模型从头训练。旧分析已正确指出这种张力，本轮不替作者发明“冻结分类器即插即用”来抹平它。忠实转述保留作者主张，科学适用问题另列；若替另一篇稿子选取表达，必须由其真实接口和训练流程决定是否能作同样承诺。

## 长短取决于此处要让读者判断什么

P3的短领域空白句接明显较长的三原因句；P4短阶段预告接长流程句；C2短评估动作句接双目标结果句。这些相邻比较比一概推崇短句或长句更有解释力。P3长句多在解释原因，P4长句多在接过程接口，C1长句多在叠贡献身份，C3长句多在压缩验证及解释；它们长的原因不同。

choices.zh.md 把矩阵、论述前景、首次新信息、已知依据和相对篇幅分开。局部英文替换绑定具体源跨度；完整中文变体另列拆句、消歧、归属显化的语义成本。中性词汇替换不算方法论收益；语法修复、异常词义推定及可能改变评价力度的选择也都明确分类。保留这个区分，才能把作者选择用于新稿，而不是把每一个原词都变成固定模板。
