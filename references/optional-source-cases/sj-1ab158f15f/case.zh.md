# OB-WSPES：资源交付与效率所得怎样共用一条主线

当系统／资源交付与独立效率结果都成立、却争夺引言中心时，按需读本例。A为作者明确主张，O为篇章或证据观察，I为编辑解释；版本与页段见[来源说明](sources.md)。本例不改变目标作者已定框架，也不规定效率必须靠后。

## 1. 先让读者知道系统比较什么

A/O：OB-WSPES将查询混淆、特征提取、攻击和评价纳入同一系统。完整引言先交系统支持的比较，再解释活动表示及查询效用／应用效用的区别；资源贡献之后，另列表示效率所得：平均准确率约0.83、约九倍加速。它保留了两项有意义的推进，没有把效率缩成普通实现步骤。

I：活动表示与两类效用提前，不是因为它们比效率更难，而是它们让读者知道“统一评价”的对象和输出。查询属性变化与搜索结果变化不必一致；不先区分两者，后面的结果就容易被误读。九倍不能替代这一解释，却能回答系统内分析的成本问题。

A/O：QWSP此前已提供通用隐私量化框架、工具和实证，区分查询结构与语义隐私。因而不能用“此前没有实际评价”抬高资源价值；OB-WSPES需落到其结合的机制、攻击和查询／应用效用接口。

## 2. 一个可复用的句群：先交比较能力，保留效率所得

以下以源研究事实作编辑重组（I），不是论文原句或严格翻译，也不是目标论文可直接套用的模板：

> 已有量化框架能够根据攻击输出评价查询隐私，而选择混淆机制还涉及另一个问题：查询属性被改变后，搜索结果是否也以同样方式变化？我们构建OB-WSPES，将混淆活动记录、攻击与效用评价纳入共同接口，以比较不同机制和设置下的结果。评价分别考察查询属性保留与搜索结果变化：在受测机制和设置中，增加假查询可能降低部分主题属性的保留程度，但搜索结果与原始结果的差异未必同步增大。在TMN与AOL数据的表示实验中，词向量还以少于高维one-hot的每用户分析时间，在区分真实与假查询时取得与该基线接近的平均准确率。

I：第一句保住强前作的已有能力，并引出另一个相关判断；第二句交总体资源；第三句给资源产生的认识；最后一句保留独立成本所得。效率句没有承担证明整个评价系统有效的职责，也没有被删掉。若目标稿前文已交清效用区别，贡献中可缩短第三句；若效率是独立研究所得，仍可单列，不必为“单一主线”强压为附带短语。

O：这里的平均关系不等于每个攻击器准确率都胜出，结果列表变化也不等于已测用户满意度。源文另有跨假／真比例的整体accuracy趋势，但现有报告不足以单独确立真实查询恢复能力或隐私的变化，不以该较强趋势判断支撑本示例。

## 3. 数字保留哪项比较

O：源文Table7在同一TMN／AOL设置中比较300维词向量、28939维one-hot及5218维one-hot，九个攻击器的词向量准确率均值约0.83。约九倍与较低维one-hot的时间比较相容，源文未交代聚合公式；换成高维基线会得到更大的倍数，但这是更换比较对象。低维基线只在此表中时间较低，并非准确率等所有方面更强。

I：若段落只需交“准确率与成本关系”，可像上例保留有界结论，把具体倍数留评价。若成本就是主张，则带上表示、任务与基线报告数字；不能把它改写成相对SimAttack／QWSP的九倍完整攻击加速，或九倍端到端系统收益。

## 4. 反例：效率可以合理居前

A/O：SimAttack的引言直接突出高效、可扩展的攻击及较大用户规模的评价。它报告的158倍对应1000用户的unlinkability设置，100倍对应100用户的TMN设置，与OB-WSPES的九倍不是同一比较。

I：这个真实反例说明，若研究要交付的是扩大可承担的攻击评价范围，效率能成为任务答案。仍应说明扩大的对象、保留的攻击效果及比较条件，而不是单把最大倍数搬到开头。

同源另一种重组也可以成立（I，仍非原文引句）：

> 本文比较查询表示对区分真实与假查询的攻击成本和准确率的影响。在相同的TMN／AOL设置下，300维词向量以更少的每用户分析时间，取得与28939维one-hot接近的平均准确率。与表中用时更少的5218维one-hot相比，其每用户分析时间约为后者的九分之一。OB-WSPES的共同接口承载这项比较，并支持进一步考察不同混淆机制与效用指标。

这组把有界表示比较置于中心，资源转为比较基础；它没有声称已实现持续在线监测或固定预算吞吐。若目标论文真要以部署效率为主线，还需对应的端到端成本与适当优化基线证据，不能由此表预支。

## 5. 使用边界

I：本例细化已有价值选材原则：保住当前任务的比较对象、读者理解它所需的前提，以及其他独立成立的所得；随实际研究承诺改变前后重心。它不产生固定主次排序，不要求资源论文照搬五项贡献，也不要求已清楚的段落为套例重写。
