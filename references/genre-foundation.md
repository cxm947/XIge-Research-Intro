## 1. 核心判断

一个正常的研究引言让读者依次理解：**我们讨论什么、为何值得研究；已有工作带来了什么；还剩下什么实质问题；本文凭什么有希望推进它；本文实际做了什么；获得了什么重要结果；最终贡献是什么。** 这是读者理解的常见依赖链，不是每篇论文都必须用七段逐项填写的法则。

保持末尾的体裁职责：本文工作段正面介绍研究及其主成果，贡献总结提炼读者可以带走的新知识或能力。逐表验收、证据台账和未完成事项不能代替这两项职责。真正影响主张解释的范围条件仍需保留，只是要进入相关陈述，而非把结尾写成工作进度汇报。

本文件中的职责依赖、分支选择和改稿检验是**编辑综合**。其依据来自下述作者教材、官方教学资源与实际论文，但不是那些来源原封不动规定的段落模板，更不是 TDSC、TIFS、CCS 或 USENIX 的投稿硬性规定。

## 2. 来源提供了什么，又没有提供什么

- **Swales–Feak 作者教材：** CARS 区分建立研究领域、建立研究空间、介绍当前研究三类动作；建立空间既可指出缺口，也可延伸已有知识。教材明确给出工程变体，并把问题/假设、主要发现、价值和结构预告列为因领域而异的项。[G1]
- **Nature/Scitable 教学材料与曼彻斯特大学 Phrasebank：** 背景要服务研究需要，说明为何值得做以及做了什么；功能安排有变体，不能把建议的四组件或常见顺序读成固定段数。[G3–G4]
- **Shaw 的软件工程研究写作论文：** 贡献应指向得到的研究结果及其可带走的价值，综合多个元素也要解释新增认识。本文据此把“做了若干模块”与“建立了某种研究成果”分开。[G2]
- **Mensh–Kording 的作者写作指南：** 引言要建立研究需要，并让末段紧凑交代本文如何推进该问题。[G5]

这里存在真实的指导差异：G1 对是否在引言再报主要发现持领域化、避免重复的立场；G5 推荐结果型收束。不能把它们合成为“所有论文必须以一段结果结尾”。实际安全/系统论文也允许结果概述后接贡献列表；短型机器学习引言可以直接用“本文方法＋主要能力/成果”收束，而没有独立贡献列表。[E1–E3]

**系统／方法论文的当前起点：**方案直接接贡献，关键结果由最后一项实现与评价贡献承担；只有稿件需要且用户允许时，才在工作段末或独立成果段预告结果。贡献先选已建立的能力，再确定理解它必需的评价范围；不沿实验目录报数。这个选择响应当前分支与用户要求，不假装消除了学科差异。

## 3. 职责依赖与具体分支

把读者需要的认识与物理段落分开。下表用于选择分支和检查有没有丢失职责，实际成句统一执行[主文件](../SKILL.md)与[逐段生成程序](sentence-blueprint.md)，不再并列一套默认七段模板。

| 需要建立的认识 | 具体材料与下一步依赖 |
|---|---|
| 任务及价值 | 对象、判据和后果决定后续该比较哪些能力；用户指定的领域收窄顺序保留 |
| 已有答案与剩余问题 | 先给近邻真实能力及条件，再界定本稿问题；任务级方案与组件引文不能混淆 |
| 根因或研究障碍 | 解释所需判断为何难获得，产生设计必须满足的要求；不同根因才支持独立挑战 |
| 思路及本文研究 | 可利用关系解释选择；明确作者动作，将输入、对象或假设转成任务输出。思路可合入工作段 |
| 主要所得与贡献 | 选择回答中心问题的已完成工作及结果，再按方法、设计、评价或其他研究所得归纳 |

同一职责可以合并或展开，但它依赖的条件必须在首次使用时可得。近邻的范围限制不自动解释技术根因；使用图或模型不自动成为洞察；一项视觉分支结果不自动证明完整系统优势。合并前先指定相邻哪一句承接被删段的必要内容。

单独保留洞察段时，应有一个不依赖系统名也成立的判断；若洞察与方案只能写成同一句“结合 A/B 完成 C”，就合写。单独保留成果段时，应有需要展开解释的核心答案；否则贡献的评价项即可承担预告，不强开结果段。

## 4. 合理变体：按照研究关系选择，不按偏好硬套

### A. 当前作者的双挑战系统／方法分支

**P1 大背景→小背景→命名重要任务 → P2 必要任务背景、现有做法与应用要求 → P3/P4 两项独立应用挑战 → P5 本文工作与研究策略 → 贡献及末项实验结论。**

这是本作者相关稿件的默认。P2只补理解挑战的前提；P3/P4各从缺失能力／权衡起笔，接观察／直觉／洞察、极简已有办法及其仍不足的对照。两项挑战可独立并列或有前后依赖，但不能同根换名；设计引出的代价留在设计之后。P5先提出什么与任务，再解释策略和两项响应；贡献确认具体交付和实验结论，允许必要重叠。

不要因源例采用P2-gap布局、材料暂缺第二项根据或篇幅压力自行合段；先核对真实关系并继续有据部分。只有作者明确改变布局或研究体裁确已改变时，才选下列变体；按其研究目的保留必要职责。逐段写法见[段落程序](sentence-blueprint.md)。

### B. 紧凑方法型

已有能力与价值 → 根本限制 → 可利用的替代关系 → 本文方法与主成果。可以没有贡献 bullets；贡献已经被最后一段清楚表达时，不强加重复目录。E3 是此类反例，不能用“没有七段”判它不合格。

### C. 测量/实证发现型

现象及判断价值 → 已知事实与争议 → 未知问题及难以观测的原因 → 本文如何让该问题可观测/可区分 → 研究范围 → 主要发现 → 认识性贡献。研究设计不必伪装成算法洞察，也不必强造系统名称；认识性贡献应突出建立了什么认识。

### D. 理论型

问题与已有界限 → 未决关系 → 关键概念/证明障碍 → 本文的抽象、区分或证明思路 → 主结果及重要条件 → 与已有结果的关系和贡献。主要结果可用定理或紧凑公式表达；按目标期刊惯例安排，不套用“实验提升百分比”。

### E. 资源、基准或综合型

社区需要做出的判断 → 已有资源/认识能支持到哪 → 比较或组织障碍 → 本文构造/对齐原则 → 资源/框架及研究动作 → 因此获得的新比较、新发现或可复用能力 → 贡献。整理数量、模块总数、历史积累不能单独承担所有创新；也不能先入为主否认资源和非平凡集成本身的价值。

### F. 短通信、扩展研究和特定学科惯例

允许较快切入当前工作、仅陈述研究目标，或直接说明相对既有工作的扩展。没有必要把每篇研究塑造成前人普遍失效后的危机。对指定 venue，另核当前作者指南及同类型近期论文；这里没有完成任何具体 venue 政策核验。

## 5. 作者写法与审计写法的边界

作者写法在正文里承担论断：“本文提出 X，通过 Y 使 Z 成为可能；在指定范围内取得 R。”审计写法检查这一论断是否成立：“Table 2 支持哪条 claim；缺少哪组 baseline；还需要补什么。”后者是有用的工作，但不能替代前者。

修改失败稿时，保留真实研究事实和会改变解释的关键边界，重新写出有主语、动作、对象和成果的完整句子。把缺失证据、待核数字、潜在审稿质疑集中列在正文之后的短说明中。不得把没有做的研究写成已完成，也不得以“尚不能证明”“未来仍需”连续收束已成立成果。

**不是图表/公式禁令。** 如果一张问题示意图、一个能力对照表或一条关键定义能以更小认知成本建立本文的问题，它可以出现在引言。判断依据是其承担的论证职责及目标规范；失败的是让末尾变成证据逐项盘点，不是任何图表引用或数学表达本身。E1 引言本身包含概率和能量记号，足以反驳“一律禁止公式”的机械规则。

## 6. 从段落职责进入实际写作

从[主文件的整篇程序](../SKILL.md)分配好段落后，读取[逐段模板与程序](sentence-blueprint.md)的相应单元。围绕当前段落要交付的认识，连着考虑读者已有的对象、这次选入的事实及其根据，以及下一段接手的问题，再直接起草连续正文。需要解释或修复某个推进处时，才细看定位、解释、对照、限定、例示、宣布工作或归纳贡献等句子动作；不要求写作前为每段、每句另填分析表。

段内句数、过渡词和句法由事实及理解负担决定。全文连读时检查任务价值、已有能力、剩余问题、本文思路、实际成果与贡献是否可恢复；缺哪项关系就修哪项，已有有效内容可以保留，不以段数或逐句新增配额判定质量。
